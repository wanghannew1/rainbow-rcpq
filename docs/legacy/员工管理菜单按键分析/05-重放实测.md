## 1. 重放配方（逆向成果，后续实测直接复用）

`POST /rcpq/ria_pojo.do?method=action`，PojoAction 按请求头分流：

| 条件 | 分支 | 用法 |
|---|---|---|
| 头 `ajaxRequest: true` | 读 **原始流** | **推荐**：`Content-Type: text/plain` + 裸 JSON 体 |
| 无该头 | 读表单参数 **`data`** | `--data-urlencode "data=<json>"`（同样可用） |

JSON 体：`{"header":{"ajaxRequest":true},"body":{"dataStores":{},"parameters":{"pojo.interaction":"REQ-UTIL-procedureService-Q","synCount":"false","proName":"PKG_包.过程","paraIn":[...],"paraOutType":[...]}}}`

**三个坑（全部踩过并验证）**：
1. `paraOutType` 必须与过程 OUT 参数个数/类型一一对应（类型名小写字符串数组，如 `["varchar","varchar","number","varchar"]`）。缺失或个数不符 → 响应序列化 `net.sf.json JSONException: null object` → **HTTP 500**（调用本身可能已成功执行！）。
2. 过程失败（appCode=-1）时错误响应路径**自身崩溃**：`PojoAction.action:83 setTitle(null)`——LemisException title 为 null 时 `JSONObject.put(null)` 抛异常，**500 顶替结构化错误**。即：看到 500 ≠ 调用没执行；要看 SYS_ERR_LOG 定位。
3. `Content-Type: multipart/form-data`（浏览器实际值）会让 Struts multipart 包装器吃掉流 → 500。curl 重放务必换 text/plain。

响应形如：`{header:{...},body:{parameters:{...,para:"1$1993-02-10$33.0$...",appCode:"1",errMsg:""}}}`。

## 3. 由此修正的结论

1. **04 文档 tdbq 段**：「空壳假成功」→ 当前库状态下应为「**点击即 500**」；空壳体（P_APCODE:=1 + 全注释）依然成立——若包能编译，行为就是假成功。两级缺陷：包级（编译失败）+ 逻辑级（空壳）。
2. **DB 梳理 §8.3 列漂移 5 处 → 6 处**：新增 `PKG_RCPQ_HM`（AA97.AAA97G ×4，PLS-00302/ORA-00904）。tdbe/tion 的全过程因此不可用。
3. **环境拓扑（已按用户确认修正）**：**0.70 应用连的就是 0.60**。我此前的反证（v$session 无 0.70 池化会话 + 日志"缺失"）均有解释漏洞：① 0.70 的连接池即用即断/无空闲常驻，v$session 抓不到；② SYS_ERR_LOG 失败日志**延迟可见**（11:52 写入，~12:25 查询仍不可见，12:5x 才出现）且编译失败型日志是无文本裸异常，按名检索不到。教训：**判断应用↔库的连接关系，以部署配置为准，v$session 时点采样和日志检索都可能是假阴性**。0.60 = 生产库每夜全量镜像（SYS_ERR_LOG 含 11-13 白天业务人员的报错），本地 8090 直连 0.60。
4. **0.60 SYS_ERR_LOG 是活跃生产晴雨表**：2010→2026 连续无断档；2026 年每月 400~530 条；11-13 单日 11 名业务经办人 306 条。**新发现的真实痛点**：`PKG_费用结算.PRC_生成费用清单` 报「此费用清单已提交，无法重复提交」2026 年每月数百条——月费用结算的重复提交困扰是持续性 UX 问题。
5. **旧结论修订**：「公积金缴费基数核对 1200 次报错」实为 **2025-01 单月 1120 条** 的集中故障（+2022-01 80 条），非持续高频；「异议处理业务性拒绝」的年份分布需按同法重查后再引用。
6. 待查标记：每天 03:39-03:47 有 7 条 jiaq 会话的 procedureService 裸 LemisBusinessException（无过程名文本）——疑夜间调度（PKG_JOB/Quartz catch-up）在备份重启窗口失败，与用户备份窗口吻合，身份待确认。
