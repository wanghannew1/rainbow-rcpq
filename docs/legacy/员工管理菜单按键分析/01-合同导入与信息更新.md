# 01 · 合同导入&信息更新（tdbp）—— 全系统最常用页

> 2026-11-14。标记：**[实测]**=0.70 DOM 抓取；**[代码级]**=静态分析（行号可溯）；模板列为 xlrd 实读 .xls。过程存在性以 `work/pkg_all/` 转储 grep 验证。

## 0. 页面结构：两个 Tab，但「信息更新」整块被隐藏 ⚠

- **tab1 合同新增导入**：查询 TC90 + 5 个批量导入入口（jsp:33,121-127）。
- **tab2 信息更新**（AC01 批量更新）：`tdbp_cont.js:16` 在 page_init 里**无条件 `tab.removeChild(tab2)`** → 清空批次号/查询/重置/模板下载/导入 5 键全部不可达。**菜单名「合同导入&信息更新」名实不符**。[实测] 抓取的 HTML 里 tab2 DOM 仍在——因为是 JS 移除，佐证此隐藏是后改的。
- 本页无专属 Java 业务类（td/b/p 无目录的原因）：网格全是通用 PoJo 查询，业务全在 **PKG_派遣批量导入** 的 10 个校验/提交过程里。

**导入通用两段式**（五个弹窗同构）：
1. **校验段**：`lemis.imp.Import(importId)` 上传 Excel → `SYS_IMPORT/SYS_IMPORT_MAPPING` 配置驱动解析（ImportUtil.java:213-254，仅列宽校验）→ 写报盘暂存表（TC90_BP/BP1/BP2/BP3/BP4）+ **CE10 批次表**（saveCE10 :309-322，ACE100=SEQ_CE10_ACE100）→ 立即调「XX校验」过程逐行打 **ACE10A** 标志（字典：0失败/1成功/2不符合条件/3符合条件/4符合条件-需重点关注 [AA10]）。
2. **提交段**：「确认提交」→ `checkIsHave` 数 ace10a='3'（新签兼容 '3','4'）→ 调「XX提交」过程写正式表 → 刷新成功/失败页签。

**弹窗↔主键映射**（纠正早前猜测）：imp_tab1→import(新签)、imp_tab3→import1(解除)、imp_tab4→import2(未解除更新)、imp_tab5→import3(续签)、imp_tab6→import4(新增保险)。

## 5. 风险清单

1. **tab2 整 Tab 死键**（菜单名实不符）；恢复入口在 js:16 一行。
2. 主页模板下载隐藏且指旧模板。
3. **PKG_IMP_FZ.PRC_TC90_IMP/PRC_COMMIT_TC90_IMP 已死**（JS 注释摘除 + 主页 TC90_IMP 过滤注释）→ 旧导入链遗迹；主页面仍加载 5 个无用 ds.js。
4. 8 处遗留 `debugger;`（各 dialog js）——带调试器的 IE 会中断。
5. doQueryTab1 store 名混用（import1-4 四个弹窗同病）→ "提交后失败页签不刷新"。
6. 续签模板下载带全员个人信息外带 + HQL 拼接。
7. checkIsHave 全站拼接 SQL（common.js:1183）。
8. 解析层仅列宽校验，业务校验全在库内过程；SYS_IMPORT_MAPPING 配置在 DB（未 dump），模板列错位无法静态发现。
9. 重复上传产生重复批次（无去重）。
10. ACE10A='4' 仅新签有——四个弹窗提交只认 '3'，'4' 行易被当失败忽略。
11. **新增保险"提交成功"≠生效**（要等 '21' 审核）——业务误读高发点。
12. 反编译文本列名漂移（ATC9WC 等）以表结构与 spec 为准。

## 6. 与既有 DB 盘点的交叉结论

- **PKG_IMP_FZ@1195（ATC9WF 编译错）的风险收敛**：tdbp 侧已不调 PKG_IMP_FZ；该包剩余被前端引用的是 **TC9W_HZ_IMP 系（员工异动回盘批量导入，tdck_dialog_import_bz*.js）**——风险仅在此线（见 DB 梳理文档 §8.3 更新）。
- CE10 导入批次表（5.6 万行）= 本页五弹窗 + 各导入页共用的批次台账；ACE10A 状态字典解释了此前 DB 盘点中各 `_BP` 暂存表 ace10a 列的取值。
- TC90_BP~BP4 五张暂存表的行数（合计约 28 万）即历史导入批次体量；正式表写入只在"提交"段发生。
