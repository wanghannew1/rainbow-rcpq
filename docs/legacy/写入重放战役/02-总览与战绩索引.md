## 四、digest 破解全案(00 卷的完整取证过程)

现象: proc 通道 500, query 通道全通。取证路径:
1. catalina.out: `NPE at PojoAction.action:82`(反编译=dc.setCode, dc==null 即 parse 失败)。
2. DataCenterReaderImpl 字节码: reader 有防篡改校验, 解析异常被自己 logger 吞掉,
   真错误 `parse:84 传输的数据被篡改` 写在同日志。
3. ASCII proName 对照: 解析过了, :83 setTitle(null) 另案——证明摘要只对非 ASCII 失准。
4. 服务端算法(reader+Escape 双反编译): `sha1_hex( Escape.escape(body).toLowerCase().getBytes() )`
   与 header `digest` equalsIgnoreCase 比对; **digest 头存在即必验**(AppContext 传递, 勘正
   原注释"备而不用"); 头缺席=跳过校验(rpc.sh 因此免疫)。
5. 浏览器权威: unieap/rpc.js `hex_sha1(escape(json).toLowerCase())`, JS escape 语义=
   仅 ASCII 字母数字+`@*_+-./` 不转义。
6. 根因: Python `str.isalnum()` 汉字返回 True(Unicode 语义)→中文裸进摘要。修复后与
   jar 真 Escape 逐字节对表(摘要 642865d73ec23cd9a061cff0fed464dcc0f432f5 双侧一致)。
7. ⚠ rainbow-rcpq 原版 replay2.py 仍带此 bug, 待回移。
