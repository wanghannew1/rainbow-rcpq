## 行为语义/教训

1. **克隆-复活模型**: 调转申请=克隆 TC90_LIST(送审态), 审核过=克隆转生效——旧单元原行不动,
   新单元以克隆行生效。重写要保留"一个人生涯多份 TC90_LIST 分单元并存"的模型。
2. **'26' 分支的 ATB900 语义**: `旧单元;新TB93键`——填错段值 → NO_DATA_FOUND → 500。
   本次第一发把新单元段填成 AAB001(151) 而非 ATB930(37312), 审核哑火; **修单别走原交互**
   (tdblService 恒 INSERT+克隆, 更新会重复克隆), 测试行直接 JDBC 修字段属清理纪律范畴。
3. 首轮失败的 NPE 教训见律⑬。

## 形状律增补

⑬ **嵌套 parameters 参数**: 服务端 `dc.getParameter("parameters")` 取的是 body.parameters 里
   **名为 "parameters" 的子对象**(`{"parameters":{"atc900":...,"atb930":...}}`), 不是 parameters 本身。
   直发平铺键 → 服务端 map=null → NPE → :83 崩。tdbl 型服务(参数驱动而非行驱动)全用此线型。
⑭ 响应不回显配号时的取号法: DB 按内容标记查(tdbl 提交响应无 atb910)。
