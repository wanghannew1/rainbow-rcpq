## 二、结算引擎结构(PKG_费用结算 748~2404 行实读 + 实测)

```
TC93(180列) 是中心表: 输入=工资项 atc93W1~W26(奖金/加班/餐补…), 输出=计算列
  atc93aa 应发 / atc93ab 应税 / atc93ad 个税 / atc93s 实发 / BBA00x 单位缴 / BAA2xx 个人缴

守卫链: TB93 单元行 → AB01 单位行 → TC93 计数(有'1'已确认→拒绝; 全空→自动调工资花名册生成)
        → 待审核员工守卫(TB91'2'/TC90'2' 存在→拒绝) → 逐人循环计算(读 AA92 比例参数)
清单确认(LB=1): UPDATE TC93 SET AAE214='1' → 五险种关联表盖章(TC05/TD04/AC10/TC07)
        → 三表联接校验 AB01×TB90×TB93 → 自插 TB96 结算费用总表
```

## 三、新形状律(续卷 37)

**㉘ TB93 主键是 ATB900** — ATB930 只是"结算单元流水号"列, 直接插 ATB930 会 ORA-01400。TB90 同构(ATB900 主键)。

**㉙ 结算确认要三表联接** — `AB01×TB90×TB93 WHERE A.AAB001=B.AAB001 AND B.ATB900=C.ATB900 AND C.ATB930=参数`; 缺 TB90 协议行 → "费用清单确认出错，错误原因结算单元信息选择错误"。夹具必须有 TB90 行(ATB900 与 TB93.ATB900 一致)。

**㉚ 生成费用清单是双模式 proc** — LB='1' 确认(自插 TB96 头), LB='2' 撤销确认。**TB96 头由确认过程自插**, 预插会触发"此费用清单已提交，无法重复提交"防重守卫。

**㉛ 部分提交怪癖(重大)** — 业务错误(OUT 置错返回)时, proc **先前已执行的 UPDATE 已生效**(确认 UPDATE 在后续校验失败时已落库); 与 ORA 异常路径的语句级回滚不同。撤销结算守卫因此误报"已确认"。重写必须把"先改后校验"修正为"先校验后改", 或包事务。

**㉜ 提取上月工资语义** — 上月=参数 atc931-1(非 SYSDATE 推算); 逐行复制(人须审核态 '3'/'5'+atc90av 守卫), 重配号+AAE214='0'+操作员盖章; 目标月有已确认行则拒绝。
