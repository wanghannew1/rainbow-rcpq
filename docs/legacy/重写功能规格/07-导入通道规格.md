# 重写功能规格 07 — 导入通道

> tdbp 合同导入&信息更新(菜单标注"最常用")的五导入线 + SY_IMPORT 配置驱动引擎 + 部署级故障记录。

## 一、传输协议(逆向完成)

```
POST /rcpq/ria_pojo.do?method=doImport
Content-Type: multipart/form-data
字段:
  uploadFile: .xls 文件(unieap FileInput 默认名)
  importId:   SY_IMPORT 配置键(驼峰, 服务端转小写查询)
  javabean:   自定义 bean(可空)
  parameters: JSON 字符串(可空)

响应:
  成功: {succeed:true, ce10:[批次号数组], baz002:N, errors:[]}
  Lemis 错误: {succeed:false, msg:'...'}
  非 Lemis 异常: {succeed:false}(无栈无日志)
```

## 二、配置体系

### SYS_IMPORT(导入线注册)
| 列 | 说明 |
|---|---|
| IMPORT_ID | 导入线标识 |
| TEMPLATE_ID | 模板 ID(=IMPORT_ID) |
| FILE_SUFFIX | xls |
| SHEET_INDEX | 解析 sheet 序号 |
| DATA_FROM | 数据起始行(0 基，前 N 行为表头) |
| ENTITY_NAME | 暂存表全限定名(如 TC90_BP) |
| PROC_NAME | 校验/提交过程(可空=页面驱动) |
| JAVA_BEAN | 自定义处理 bean(可空) |
| MIN_AVAI_CELL | 最小有效单元格数 |

### SYS_IMPORT_MAPPING(列映射)
| 列 | 说明 |
|---|---|
| IMPORT_ID | 关联导入线 |
| DATA_FORM | Excel 列序号(0 基) |
| DATA_TO | 实体属性名(驼峰) |
| DATA_TYPE | 数据类型 |
| MAPPING_TYPE | 映射类型 |

### 暂存表
- TC90_BP: 员工信息暂存(ace10a '3'=合格/'2'=不合格)
- TC90_BP1: 合同终止信息暂存
- TC93_BP1: 工资导入暂存
- TC95_BP: 工资报盘暂存

## 三、处理流程

```
Excel 上传 → POI 解析(按 SHEET_INDEX+DATA_FROM) → 按 MAPPING 逐列填实体
→ hibernate save(暂存表) → CE10 批次登记
→ (页面驱动) PRC_CHECK_xxx 校验 → PRC_COMMIT_xxx 提交落库
```

### 校验过程
| 线 | 校验过程 | 提交过程 | 所属包 |
|---|---|---|---|
| tc90_imp 员工信息 | PKG_IMP.PRC_CHECK_TC90_IMP | PKG_IMP.PRC_COMMIT_TC90_IMP | PKG_IMP ⛔ INVALID |
| tc90_impdel 合同终止 | PKG_IMP.PRC_CHECK_xxx | PKG_IMP.PRC_COMMIT_xxx | PKG_IMP ⛔ |
| tc90_wy 信息更新 | PKG_RCPQ_WY.PRC_COMMIT_XZ/ALL | 同左 | PKG_RCPQ_WY ⛔ |

**全部提交过程所在包(INVALID/CONFIRMED-DEAD)→ tdbp 五导入线提交功能当前全死。**

## 四、遗产缺陷(导入通道专属)

### D3-1. 引擎部署级静默死亡
- **现象**: 8091 部署上所有 importId 一致 {succeed:false}(无栈无日志)
- **排除**: 序列/实体映射/POI 兼容/模板/单元格格式/字段名全绿
- **定性**: 引擎内部非 Lemis 异常被 catch(Exception) 吞掉(无 printStackTrace)
- **根因**: 需 JVM 级观测(debug agent / 还原生产部署位)

### D3-2. POI 3.2(2008 年版)
- 2008 年的 Apache POI，不支持 xlsx，仅 HSSF
- **重写规则**: 使用现代 POI 或 Apache Excel 流式 API

### D3-3. 提交过程 PKG_IMP 死包
- ATC90T1/T2/T3 列漂移(TC90 扩展列不在表中)
- 即使暂存数据就位，提交也会失败

## 五、重写设计建议

1. **上传**: 标准 multipart REST API
2. **解析**: Apache POI 5.x(流式读取 SXSSF)
3. **配置**: YAML/JSON 定义列映射(非 DB 表)，版本控制
4. **暂存**: 统一暂存表+批次管理(保留 CE10 模式但简化)
5. **校验**: 独立校验服务(非存储过程)——可单元测试
6. **提交**: 事务性批量提交，失败完整回滚+错误报告
7. **错误**: 结构化错误清单(行号+列名+原因)，前端可直接展示

## 六、编译期防护(对照 03 卷遗产缺陷)

| 遗产缺陷 | 重写防护 |
|---|---|
| POI 3.2 只支持 xls | 使用 xlsx(现代格式) |
| 列映射在 DB(无版本控制) | YAML 配置文件+版本控制 |
| 校验过程在 PLSQL(不可单测) | Java 服务层(可单测) |
| 错误被吞(succeed:false 无详情) | 结构化错误清单必须返回 |
| 暂存表与提交表同构(列漂移放大) | 暂存 DTO 独立定义(不继承提交表) |
