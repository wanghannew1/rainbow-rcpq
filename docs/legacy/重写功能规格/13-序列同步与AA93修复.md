## 根因终判

**SEQ_AA93_AAA930 在 dmp 导入后被重置为 START WITH 1**（Oracle dmp 导入默认行为），
但 AA93 表内已有 dmp 携带的 AAA930=1~17 的数据行。序列 NEXTVAL 从 1 开始 → 立即撞 PK。

**这不是假死，是真碰撞**——序列从 1 开始返回值，每行都撞已有数据。
用重复 NEXTVAL 跳过碰撞区（17 次）后，序列值到达 18 > 表内 max(17) → 插入成功。

## 修复方法（标准 DBA 操作）

```sql
-- 方法 1: 重复 NEXTVAL（无需 DDL，已验证）
-- 连续 SELECT SEQ_AA93_AAA930.NEXTVAL FROM dual 直到 > 表内 MAX(PK)

-- 方法 2: ALTER SEQUENCE 快进（需 DDL 权限）
ALTER SEQUENCE SEQ_AA93_AAA930 INCREMENT BY 100;
SELECT SEQ_AA93_AAA930.NEXTVAL FROM dual;  -- 跳到高位
ALTER SEQUENCE SEQ_AA93_AAA930 INCREMENT BY 1;
```

## 重写防护规则(#15)

**dmp 迁移后所有序列必须重同步到表内 MAX(PK)+1。**
迁移脚本应包含: 按表逐序列检查 last_number vs max(pk) → ALTER SEQUENCE 重设。
这是标准数据迁移后置步骤，遗漏会导致所有新增操作报 PK 冲突。
