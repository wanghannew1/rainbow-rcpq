# 重写功能规格 04 — 参保异动流程(社保/市医保/省医保)

> TC9W(社保) / TC9W1(市医保) / TC9W2(省医保) 三表同构异名族。
> 报增→确认→回盘 全生命周期 + 打回/终止/变更/参保地迁移分支。

## 一、表族模型

| 表 | 险种 | PK | 明细键 |
|---|---|---|---|
| TC9W | 社保 | ATC9W0 | AAC001+AAE002+AAA030 |
| TC9W1 | 市医保 | ATC9W0 | 同构 |
| TC9W2 | 省医保 | ATC9W0 | 同构 |

三表字段严格同构(hibernate 映射独立但列集一致)。所有报增/报减/回盘过程均按此模型操作。

## 二、报增流程

### 2.1 按人报增(单人行)
```
过程: PKG_保险人员增减.PRC_社保报增员工(PRM_ID, PRM_AAE002, PRM_AAA030, PRM_AAA020, PRM_AAE011, OUT CODE, OUT MSG)
     PKG_保险人员增减.PRC_市医保报增员工(同构)
     PKG_保险人员增减.PRC_省医保报增员工(同构)
```
- PRM_ID = TC90.ATC900(逗号分隔可批量)
- 写入: TC9W 单行 INSERT(TC90→TC9W 逐字段复制 via PRC_社保增减赋值)
- 戳记: AAE011=经办人, AAE036=SYSDATE, ATC9W1='1'(报增), ATC9W8='1'(已生成)
- TC08 不在此过程写入面内

### 2.2 户头级重生成(整户头)
```
过程: PKG_保险人员增减.PRC_市医保人员增减(PRM_AAA030, PRM_AAE002, PRM_FLAG, PRM_AAE011, PRM_AAA110, OUT CODE, OUT MSG)
```
- PRM_FLAG: '1'=报增, '3'=报减
- **先删后按视图再造**(行消失风险: 合成员工不满足视图条件)
- 回盘锁: ATC9W8='4' 行存在时拒绝(当月数据已经回盘)

### 2.3 增减确认
```
过程: PKG_保险人员增减.PRC_市医保人员增减(同上，真名)
```
⚠ 页面 JS 引用 `PRC_医保增减确认` = **幽灵过程**(包 spec 无声明)

## 三、报减流程

### 3.1 保存通道(非过程)
```
交互: REQ-e08a0dedfc744efa9b3a759ec156e326 @ tdcbe_cont
行: {aac001, aac002, aac003, aaa030, aae002=月, atc9w1='3', atc9w8='3', aae011, _t=1}
```
- PK ATC9W0 由 hibernate 实体序列配号(从 1 起计数，与 proc SEQ 配号并存)

### 3.2 前置条件
- 报减行需先有报增行(同户头同月)
- AAA030 从页面 QuickSearch 选择(AA03 表)，与 TC90 解耦

## 四、审核链

### 4.1 COMFIRM_SH 分支(ATB911 驱动)
| ATB911 | 分支 | 写入 |
|---|---|---|
| '20' 新增 | TC90.ATB90R←'3' | 仅置状态 |
| '21' 参保变更 | TC92 `_后`列→TC90 141 列 | 按字段映射刷新 |
| '25' 姓名/身份证 | AC01/TC90/TC90_LIST/TC93 **4 表按 AAC001 同步** | 键缺→静默 0 行 |
| '23' 终止 | ATB90R←'5' + TC90_LIST 终止 + TC93.ATC93V='5' + INSERT TC90_ZZ | |

### 4.2 打回(独立过程)
```
过程: PKG_人才派遣.PRC_员工批量审核不通过(PRM_ATB910, PRM_AAE011, PRM_MSG, OUT CODE, OUT MSG)
```
- 效果: TB91.ATB912 '2'→'4'(打回)
- **COMFIRM_SH '4' ≠ 打回**(COMFIRM_SH '4' 仍通过!)
- 打回后 TC90 不变(保持提交态)

## 五、参保地变更(克隆-终止模型)

```
过程: PKG_保险人员增减.PRC_变更参保地(PRM_ATC900, PRM_XZ, PRM_AAA020, OUT CODE, OUT MSG)
```
- PRM_XZ: '1'社保 / '2'医保 / '3'公积金
- 校验链: AA12 字典含目标码 → AAA402='1' → ATC90PA='0' → TC93 当月未结算
- 效果: TC90 旧行 ATB90R→'5'(终止) + 新行(新 AAA110) ATB90R→'3'(生效)
- 前置: ATC90PA='0'(医保参保完成态)

## 六、退休停保

```
过程: PKG_保险人员增减.PRC_医保退休停保(PRM_ATC900, PRM_AAA604, OUT CODE, OUT MSG)
```
- **PRM_AAA604 = 停保年月(yyyy-mm 格式)**，非审批意见
- 效果: TC90.ATC90PA='1'(停保) + AAA602/604/609=停保年月 + AAC008 险种追加'80'

## 七、终止全周期(ATB90R 状态机)

```
'1'暂存 → '2'提交 → '3'生效 → '2'终止送审(+AAE100='0') → '5'终止生效
                → '4'打回(可重提)
```

终止送审数据侧效应:
- TC90.AAA204←AAA202(报减年月镜像)
- TC90.AAA504←AAA502 / AAA604←AAA602 / AAA904←AAA902(公积金/医保/工伤镜像)
- TC90.AAE100='0'(主记录失效)
- 以上全为**前端 JS 动作**，服务端 doTerminate 仅 17 行极薄

## 八、清理

```
过程: PKG_人才派遣.PRC_删除员工(PRM_ATC900, OUT CODE, OUT MSG)
```
- 物理删: TC90_LIST/TC90/TC93/TC08/AA97/TC90_YY
- **不删**: TB91(历史档案), TC9W1, TC92, TC9E(除非在删除列表内)
- 已生成工资拒绝

## 九、重写注意事项

1. 三表(TC9W/1/2)严格同构，可抽象为统一异动明细接口
2. ATC9W8='4' 回盘锁必须实现(当月已有回盘数据不可重新生成)
3. 报增/报减双通道并存(过程生成 + 页面 save)——重写应统一为一种
4. 户头(AA03)与员工(TC90)完全解耦，任意组合合法
5. 打回走独立过程，COMFIRM_SH 只管通过
6. ATC9W0 配号空间: proc 配号(百万段)与 hibernate 配号(从 1 起)并存
