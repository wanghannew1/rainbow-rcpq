# 重写功能规格 00 — 全局形状律与防御规则

> 从写入重放战役 00~33 卷(33 份实弹文档)中提取的跨模块全局规则。
> 每条规则都有实弹+DB 验证支撑，重写时**必须遵守**或**有意偏离并记录原因**。

## 一、通信协议层

### 1.1 DC 报文形状
- header: `{"ajaxRequest": true}`
- body: `{"dataStores":{<store_name>:{rowSet, parameters, condition}}, "parameters":{pojo.* + 业务参数}}`
- 多 store 复合: 一次 save 发多个 dataStore，每个 store 的 primary 数组承载行集
- **每个 store 的 primary 必须至少 1 行**(服务端 `getRowDataObjs().get(0)` 无条件取行，空→异常)

### 1.2 行状态标记(不可省略)
| 标记 | 含义 | 服务端行为 |
|---|---|---|
| `_t:1` | 新增(NEWMODIFIED) | hibernate save(插入) |
| `_t:2` | 未修改(NOTMODIFIED) | **跳过(静默无操作!)** |
| `_t:3` | 修改(DATAMODIFIED) | saveOrUpdate(更新) |
| `_o:{字段:旧值}` | 修改前的旧值 | TC90_BG 等审计留痕的数据源 |
| `_t` 缺省 | = NOTMODIFIED | **静默无操作(最大陷阱)** |

### 1.3 日期字段
- 必须发 **epoch 毫秒数值**(如 `1559347200000`)，不可发字符串
- 发字符串 → HibernateHelper `NumberFormatException`

### 1.4 主键策略
| 表 | PK 列 | 配号方式 |
|---|---|---|
| TC90 | ATC900 | hibernate sequence |
| TB91 | ATB910 | hibernate sequence |
| TC9W/TC9W1/TC9W2 | ATC9W0 | 过程内 sequence 或 hibernate |
| TC92 | ATC920 | hibernate sequence |
| AA03 | AAA030 | 手工/页面赋值(NUMBER) |
| AA10 | (AAA100,AAA102) | 复合主键，手工赋值 |
| AB01 | AAB001 | hibernate sequence |
| AA01/AA92/AA93/AA94 | 各自 | hibernate sequence |
| **载荷中不可猜 PK** | | 从 save 响应回显或 DB 取号 |

### 1.5 长度与格式约束
- **VARCHAR 列按字节计长度**，中文 1 字 = 2~3 字节(GBK/UTF8)
- hbm not-null 属性集 ⊇ ds.js 元数据必填集 → 取 **两者并集**一次到位
- 日期列发 epoch 毫秒数值；JAVA 字符串日期→转换后再发

## 二、存储过程调用层

### 2.1 调用通道
- URL: `POST ria_pojo.do?method=action`
- interaction: `REQ-UTIL-procedureService-Q`(固定)
- proName: **带前导空格**(照抄页面 JS 原文)
- paraIn: 参数数组(与 user_arguments IN 参数一一对应)
- paraOutType: **恒 `[]`**(服务端自动从 user_arguments 装配 OUT)

### 2.2 OUT 参数返回
- 成功: `"appCode":"1"` + `"errMsg":""`
- 业务拒绝: `"appCode":"-1"` + `"errMsg":"具体原因"` → 框架抛 LemisBusinessException(有 title)
- 技术异常: ORA-xxxx → `-30030` + errMsg=null → :83 空 title NPE → 500

### 2.3 proc 语义勘定(勿按文档推断，以过程源码为准)
| 过程名 | 真实语义 | 注意 |
|---|---|---|
| PRC_COMFIRM_SH | 审核通过/不通过 | PRM_ATB912 '3'=通过 '4'≠打回(仍通过!); 打回走独立过程 |
| PRC_员工批量审核不通过 | 批量打回 | [atb910, 经办, 打回意见] + 2OUT |
| PRC_删除员工 | 物理删除员工 | TC90_LIST/TC90/TC93/TC08/AA97/TC90_YY; TB91 留存 |
| PRC_社保报增员工 | 按人报增 | TC9W 单行 INSERT; TC08 不在此过程 |
| PRC_市医保人员增减 | 户头级重生成 | flag='1'报增/'3'报减; **先删后按视图再造** |

## 三、错误指纹速查

| 症状 | 根因 | 处置 |
|---|---|---|
| NPE @ PojoAction:82 | dc=null = 报文解析失败 | 查 DataCenterReaderImpl:84 "被篡改"=摘要错 |
| JSONException null @ :83 | 业务异常无 title | 看 LemisException/LemisBusinessException printStackTrace 块 |
| -30050 + [label]不可为空 | ds 元数据必填校验 | 补充 ds.js nullable=false 全集字段 |
| -30050 + [label]数据过长 | VARCHAR 列超长 | 按 hbm length 截断或缩短 |
| -30010 + PLS-00306 | proc 形参不匹配 | paraOutType 恒 []; 校验参数个数/类型 |
| -30010 + ORA-04063/06508 | 包体 INVALID | 二调判定(可愈 vs 真漂移) |
| PropertyValueException | hbm not-null 违反 | 补充 hbm 非空属性值 |
