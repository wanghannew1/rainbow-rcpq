# 重写功能规格 05 — 工资计算与花名册

> 平均工资计算(个人/按单元)、应发工资花名册生成、工资项目细项维护(AA90)。

## 一、平均工资计算(个人)

```
过程: PKG_人才派遣公共.PRC_计算平均工资
      (PRM_AAC003, PRM_AAC002, PRM_KSNY, PRM_JSNY, PRM_LB,
       OUT PRM_PJGZ, OUT PRM_CODE, OUT PRM_MSG)
```

- 输入: 姓名+身份证+起止月+类别标志
- 输出: PJGZ=平均工资(VARCHAR，经 OUT 参数返回)
- 数据源: TC93(工资明细) 按人员+月段筛选
- 遗产缺陷: 零覆盖人员 → ORA-01476 除零 → 500

## 二、平均工资计算(按结算单元)

```
过程: PKG_工资发放.PRC_按单位计算平均工资
      (PRM_ATB930, PRM_KSNY, PRM_JSNY, PRM_LB, PRM_NZJ, OUT CODE, OUT MSG)
```

- 按结算单元+月段计算
- 幻影月段(无数据) → appCode=1 空操作

## 三、应发工资花名册生成

```
过程: PKG_工资发放.PRC_工资花名册前台
      (PRM_ATB930, PRM_ATC931, PRM_AAE011, OUT CODE, OUT MSG)
```

- 按结算单元+年月生成花名册
- **副作用**: 内部 INSERT INTO AA93(税率级次表)——重跑不清旧行 → ORA-00001
- 遗产缺陷: 重跑花名册 = PK 冲突崩溃(过程不清理先前的级次行)

## 四、工资项目细项维护(AA90)

### 4.1 修改=换行式(与参保地变更同族)
```
服务: tddaService.updateAa90 @ tdda_dialog_mod
交互: REQ-491c60023d8c4d39bb23633b9c15786a(GUID)
```

```
isModify 行(_t=3 + _o) →
  新建无 PK 实体 → 显式拷 12 字段(排除 aaa900) → saveOrUpdate(插入新行)
  → bulkUpdate 按旧 PK 删旧行
```

- **isModify() 门**: _t=1 不被认可 → 200 静默无操作
- AAA900 配号: hbm 生成器(连续递增)，与手工夹具号并存
- 拷贝白名单 12 字段(显式枚举)，载荷中其他字段被刻意排除

### 4.2 AA90 表结构
| 列 | 类型 | 说明 |
|---|---|---|
| AAA900 | NUMBER(PK) | 序列配号 |
| ATB900 | NUMBER | 合同/单位合同 ID |
| AAA901 | VARCHAR | 排序序号 |
| AAA902 | VARCHAR | 工资项目名称 |
| ATB930 | NUMBER | 结算单元 |
| AAA810 | NUMBER | 标准(基数) |
| AAA800 | NUMBER | 数量 |
| ACB208 | VARCHAR | 标志 |

### 4.3 审计留痕
- 处理层再提交时 TC90_BG 逐列留痕(驱动源=_o 字典)
- **取消路径不清理 TC90_BG**(孤儿留痕)

## 五、重写注意事项

1. 平均工资计算应有零覆盖防护(结构化"查无此人")
2. 花名册生成应有幂等性(重跑不冲突)——遗产每次插 AA93 无清理
3. AA90 换行式修改可简化为 UPDATE(新系统无 PK 更换必要)
4. TC90_BG 审计留痕应自动管理生命周期(关联删除)
5. PRC_GET_MONEY(10IN) 为五险一金计算核心——需完整重写而非搬运
