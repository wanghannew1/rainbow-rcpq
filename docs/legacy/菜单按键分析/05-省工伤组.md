## 2. 员工省工伤报减申请（td/c/bo/tdcbo_cont.jsp）[实测：生成 flag='3' **HTTP 500 执行报错**——已定位根因，见下]

### ⚠ 报错根因（2026-11-13 定位，两层叠加）
1. **过程层**：省工伤 flag='3' 分支内存在未加 NO_DATA_FOUND 保护的 SELECT INTO——当月无减员数据时抛 `ORA-01403: 未找到任何数据`，过程捕获后返回 appCode=-1（"生成工伤异动信息出错"，SYS_ERR_LOG 12:45:54 有记录）。其他四个险种的报减分支对此情况优雅返回零行，**唯独工伤报减会炸**。
2. **框架层**：`PojoAction.action` 错误路径 `dc.setCode(le.getErrno())`（PojoAction.java:82）对 LemisException 抛 NullPointerException（框架 bug）——导致客户端收到裸 500 而不是结构化错误 JSON，真实错误信息只存在于 SYS_ERR_LOG。

**结论**：当月确有减员数据时该功能可能正常（未验证）；无减员数据时点击"生成报减名单"必报系统错误。属于"低质量但危害有限"的缺陷（事务回滚，无脏数据）。

### ✅可用按键
生成报减名单 💾 `PRC_省工伤人员增减`(flag='3')；查询已生成报减名单🔍；导出🔍；清空条件🖥。
