## 状态字段（五大名单表 TC9W/TC9W1/TC9W2/TC9W3/TC9U 通用）

| 字段 | 含义 | 实测库内分布（2026-11-13） |
|---|---|---|
| ATCxW8 | 审核状态 1暂存→3已提交→4已回盘 | **'3' 在全部 5 表历史零存在**；TC9U 连 '4' 都是零（公积金从未走完回盘） |
| ATCxW2 | 申报状态 0/1 | "已申报/未申报"键置位 |
| ATC9WF/ATC9WH | 回盘成功标志/时间 | 回盘页"报增/报减成功"键写入 |

## 实测验证过的硬结论

1. '1' 暂存：生成过程落库 [实测]（TC9W 80 行）
2. '3' 已提交：确认过程 ❌ 全部不存在（HTTP 500），但 JS 的 save 半通道**能把 '3' 写进库** [实测：atc9w8 1→3 + BAZ002 盖章]——由于按钮隐藏/过程死，历史库 '3'=0
3. '4' 已回盘：TC9W/1/2/3 大量存在（历史回盘真实发生过）；触发过程 `各险种异动回盘校验` ✅ 存在
4. 公积金 TC9U 无 '4'：**根因已定位**——`PRC_公积金异动回盘校验` 中 `UPDATE TC9U SET ATC9U8='4'` 语句**被注释禁用**（校验仅更新 TC9W_BP02 回执），公积金名单永远停在 '1' [包源码实证]
