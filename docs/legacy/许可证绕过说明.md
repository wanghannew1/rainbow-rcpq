# 许可证绕过说明（deploy/license-bypass/）

> 本目录下的类用于绕过系统内的许可证（License）校验。原始 `unieap.license` 文件已过期（bak 目录最新备份 2026-03），且原部署只绕过了其中一个校验类，导致登录/报表功能报 `License expired`。以下说明每个类的**作用、校验链证据**，以及**为什么单独部署的 class 能覆盖 jar 里的原始类**。

## 1. 绕过类清单

| # | 类 | 所在 jar | 作用 | 报错现象 |
|---|---|---|---|---|
| 1 | `com.neusoft.unieap.misc.license.Check` | unieap-platform.jar | 工具端（LicenseCommand 上传 license 文件时调用 `checkFormat`） | 无（非运行时校验） |
| 2 | `com.neusoft.unieap.misc.protection.CustomCheck` | unieap-platform.jar | **UniEAP 平台运行时授权校验入口**：`check()` 驱动整个平台 license 校验 | 登录页直接输出 `License expired`（HTTP 200 纯文本） |
| 3 | `com.neusoft.report.engine.security.licence.ProtectionCheckTask` | unieap-report.jar | **报表引擎 license 状态检查**：`getProtectionInfo()` 非 0 即抛 `ReportException: License expired` | 报表功能 HTTP 500 `License expired` |
| 4 | `com.neusoft.report.engine.security.licence.ProtectionManager` | unieap-report.jar | **报表引擎版本功能限制**：`checkEdition()` 低于要求版本抛 `(1006)该版本此功能限用` | 报表功能 HTTP 500 `(1006)该版本此功能限用` |

**注意**：UniEAP 平台授权（类 2）与报表引擎授权（类 3/4）是**两套完全独立的机制**，分别由 unieap-platform.jar 和 unieap-report.jar 各自实现，必须分别绕过。只绕过其中一套，另一套仍会拦截。

## 2. 各绕过类的校验链（反编译字节码证据）

### 2.1 CustomCheck（UniEAP 平台）

```
EAPActionServlet.init / ProtectionCheckTask（平台版定时任务）
  → CustomCheck.check(boolean)
    → ProtectionSupport.checkLicense(boolean)
      → com.jp.protection.pub.LicenseHost.checkLicense(...)   ← 第三方 Protection.jar
      → License.getLicenseState() != 2 → 返回 false（license 过期/无效）
        → ProtectionSupport$1（LicenseHostListener.licenseExpired 回调）
          → ProtectionConfig.errMsg = DecodePasswd(err2)   // "License expired"

EAPActionServlet 每次请求处理
  → ProtectionConfig.errMsg != null
    → response.getWriter().write(errMsg) + return    ← 登录页输出 "License expired"
```

**绕过方式**：假 `CustomCheck.check()` 直接返回 `true`，且**不实例化 ProtectionSupport** → LicenseHost 不初始化 → `licenseExpired` 回调不触发 → `errMsg` 保持 null → 拦截消失。

### 2.2 ProtectionCheckTask（报表引擎）

```
RAOMgr.getPermitRAO(int)
  → byte info = ProtectionCheckTask.getProtectionInfo()
  → if (info != 0) throw new ReportException(getProtectionState(info))   // "License expired"
```

**绕过方式**：假 `ProtectionCheckTask.getProtectionInfo()` 恒返回 `0`（0 = 有效）。

### 2.3 ProtectionManager（报表引擎版本限制）

```
LongResultCache.<init> / NeuReport / MultiServerCache / BarcodeFacade /
FusionChartBuilder / OdsExporter / PdfExporter / Security ...（10+ 处）
  → ProtectionManager.checkEdition(int edition)
    → if (instance.edition_mark < edition) throw Trace.error(1006)   // "该版本此功能限用"
```

**绕过方式**：假 `ProtectionManager.checkEdition(int)` 空实现，其余方法安全返回（`getInstance` 单例、`check_user/check_template/check_version` 返回 true、`isChecked` 返回 true）。

## 3. 原理：为什么单独部署的 class 能覆盖 jar 里的原始类

### 3.1 Tomcat 的类加载顺序

Tomcat 每个 Web 应用使用独立的 `WebappClassLoader`，其**搜索顺序**（Java EE 规范 + Tomcat 实现）：

```
① WEB-INF/classes/          ← 应用自身类（目录，最优先）
② WEB-INF/lib/*.jar         ← 应用依赖 jar
③ 父加载器（系统/公共 jar）
```

`WebappClassLoader.loadClass()` 先在 `WEB-INF/classes` 目录找，再扫描 `WEB-INF/lib` 的 jar。**只要同名同包名的类出现在 `WEB-INF/classes` 下，jar 里的原始类就永远不会被加载**——这就是"单独部署一个 class 就能覆盖 jar 类"的根本原因。

### 3.2 适用条件

1. **包名 + 类名必须完全一致**（如 `com.neusoft.unieap.misc.protection.CustomCheck`）；
2. **方法签名必须与 jar 版一致**（JVM 按"方法名 + 参数类型 + 返回类型"链接）。`EAPActionServlet` 调用 `CustomCheck.check(Z)Z`，假类必须提供同样签名的 `public boolean check(boolean)`，否则 `NoSuchMethodError`；
3. **静态方法同样被覆盖**（类加载级别生效，与实例/静态无关）；
4. **内部类的桥方法**：jar 版类如果有内部类（如 `ProtectionCheckTask$Evictor`），编译器会生成 `access$xxx` 静态桥方法供内部类访问外部类私有成员。假类需补上相同签名的桥方法，否则内部类被加载时会 `NoSuchMethodError`。

### 3.3 编译与部署

`deploy/setup.sh` 步骤 6 用 `javac -source 1.7 -target 1.7` 编译（与 jar 版字节码版本一致），输出到：

```
WEB-INF/classes/com/neusoft/unieap/misc/license/Check.class
WEB-INF/classes/com/neusoft/unieap/misc/protection/CustomCheck.class
WEB-INF/classes/com/neusoft/report/engine/security/licence/ProtectionCheckTask.class
WEB-INF/classes/com/neusoft/report/engine/security/licence/ProtectionManager.class
```

- `CustomCheck` 不依赖第三方类型，可直接编译；
- `ProtectionManager` 引用 `com.jp.protection.pub.License`（Protection.jar）和 `ReportException`（unieap-report.jar），编译需加 `-cp`；
- 部署后**必须重启 Tomcat**（类加载发生在应用启动时）。

## 4. 排查新校验点的方法

若某功能仍报 license 类错误，按以下步骤定位新校验点：

1. 从报错堆栈找抛出 `ReportException`/license 异常的类（如 `xxx.checkEdition`）；
2. `unzip -l` 定位该类所在 jar（lib 下逐个 `unzip -p | grep -a "License expired\|1006"`）；
3. `javap -p -c` 反编译该类，确认校验逻辑与**调用它的所有类**（`grep -rl "类路径"`）；
4. 按第 3 节规则写假类覆盖（方法签名 + 桥方法）；
5. 加入 `deploy/setup.sh` 步骤 6 并部署重启验证。
