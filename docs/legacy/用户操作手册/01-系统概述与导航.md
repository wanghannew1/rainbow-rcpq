# 彩虹人才管理系统 — 用户操作手册

> 本手册从**业务操作人员**角度描述系统的全部功能与操作流程。
> 覆盖 166 项菜单、人才派遣业务全生命周期。
> 每个操作步骤均有对应的系统页面和按钮名称。

---

## 第一章 系统概述

### 这套系统是做什么的？

这是一套**劳务派遣公司业务管理系统**。劳务派遣公司的核心业务是：
作为用人单位与劳动者签订劳动合同，然后将劳动者派遣到实际用工单位（如学校、医院、企业）工作。

系统管理从**签约用工单位** → **招人入职** → **每月发工资缴社保** → **员工离职** 的完整业务闭环。

### 系统里有三种"对象"

| 对象 | 说明 | 类比 |
|---|---|---|
| **单位**（AB01） | 与派遣公司签约的用工单位 | "客户" |
| **个人**（AC01） | 被派遣的劳动者 | "员工" |
| **员工**（TC90/TC90_LIST） | 个人被派遣到某单位工作的记录 | "合同关系" |

一个"个人"可以被派遣到不同"单位"（不同时期），每次派遣产生一条"员工"记录。

### 角色分工

| 角色 | 做什么 | 对应菜单 |
|---|---|---|
| **前台业务员**（派遣前台） | 录入申请：新增员工/终止/变更/报增报减等 | 员工管理 + 员工异动/补退费管理 |
| **审核员** | 对前台提交的申请进行审核 | 员工信息审核 + 审核信息处理 |
| **财务/工资** | 工资计算、发放、发票、到账 | 派遣费用管理 + 资金管理 |
| **社保经办** | 五险一金基数确认、报盘回盘 | 员工异动/补退费管理（社保/医保/公积金子菜单） |
| **管理员** | 系统参数、代码字典、区划维护 | 系统参数信息管理 |

## 第二章 系统登录与导航

### 登录

1. 打开浏览器访问系统首页
2. 输入用户名和密码 → 点击登录
3. 登录后左侧显示菜单树，菜单项由你的**角色**决定（不同角色看到不同菜单）

### 菜单结构（八大模块）

```
■ 人才派遣管理           ← 核心业务（最常用）
  ◆ 单位协议管理         ← 管理与用工单位的协议
  ◆ 员工管理             ← 管理派遣员工全生命周期
  ◆ 员工异动/补退费管理  ← 五险一金报增报减/基数/回盘/税务
  ◆ 派遣费用管理         ← 工资计算/费用结算
  ◆ 参数管理             ← 社保参数/所得税参数/异动期
  ◆ 统计查询             ← 各种查询报表
  ◆ 提醒事项             ← 提醒管理

■ 基本信息管理           ← 单位/个人基础数据维护
■ 综合信息管理           ← 问题管理平台/系统参数/代码字典
■ 资金管理               ← 发票/工资发放/到账/垫付
■ 事项管理               ← 退休/工伤/生育津贴
```

## 第三章 员工生命周期操作（核心流程）

### 3.1 新增员工（从入职到生效）

> 操作角色：前台业务员 → 审核员

**第一步：登记员工信息（前台业务员）**

1. 菜单 → **员工管理** → **新增员工信息申请**
2. 页面分上下两区：
   - 上区：员工基本信息表单（姓名、身份证号、联系方式、单位、岗位、工资等）
   - 下区：审核信息（自动生成"XXX于X日新增员工信息,请审核"）
3. 如有**银行账号**，填写折子号信息（代发工资需要）
4. 如需**补缴社保/公积金**，勾选补缴选项并填写补缴起止月份
5. 点击 **【暂存】** → 系统提示"暂存成功，新增员工尚未生效，请及时提交到审核"
   - 此时员工状态 = **暂存**（ATB90R='1'），尚未生效
6. 确认信息无误后，点击 **【提交到审核】**
   - 系统弹出确认框 → 点确定
   - 员工状态变为 **提交待审**（ATB90R='2'）
   - 系统自动生成审核单（TB91 表，ATB911='20' 新增类型）

**第二步：审核（审核员）**

1. 菜单 → **员工管理** → **员工信息审核**
2. 查询条件选"提交未审核" → 查出待审员工列表
3. 勾选要审核的员工 → 点击 **【批量审核通过】**
   - 或者双击某行进入详情 → 单笔审核
4. 审核通过后，员工状态变为 **生效**（ATB90R='3'）
   - 此时该员工正式成为派遣员工，可以报增社保

**第三步：社保经办处理（社保经办员）**

1. 菜单 → **员工管理** → **审核信息处理**
2. 查询待处理的新增员工 → 点击进入处理页面
3. 核对信息 → 点击 **【提交】** 或 **【取消】**
   - **提交**：系统在 TC90_BG 表逐列留痕变更记录
   - **取消**：物理删除该员工及审核单（用于错误数据）

### 3.2 合同终止或解除（离职流程）

> 操作角色：前台业务员 → 审核员

**第一步：发起终止申请**

1. 菜单 → **员工管理** → **合同终止或解除申请**
2. 查询条件选"已生效" → 查出在职员工列表
3. 勾选要终止的员工 → 点击 **【终止申请】**
4. 填写终止日期、终止原因（如"个人辞职"、"合同到期"）
5. 系统按用工性质分流：
   - **劳务工**（AAE00P='2'）：调过程立即终止，不走审核
   - **派遣工/保险代理**（AAE00P='1'/'5'）：走审核流，生成 TB91 单（ATB911='23'）
6. 点击确认 → 员工状态变为 **终止送审**（ATB90R='2'）
   - ⚠ **注意**：此时员工主记录 AAE100 已即时置'0'（失效）——即使审核还没通过

**第二步：终止审核**

1. 菜单 → **员工管理** → **员工信息审核**
2. 查询终止类待审员工 → **【批量审核通过】**
3. 审核通过后，员工状态变为 **已终止**（ATB90R='5'）
   - 系统同步处理 TC90_LIST 终止、TC93 费用置终、TC90_ZZ 留痕

**第三步：处理（如有退费）**

1. 菜单 → **员工管理** → **审核信息处理**
2. 查已审核的终止员工 → 进入处理页面
3. 如有多缴费用，系统生成退费明细（TC9E/AC10）
4. 处理完成后员工正式离场

### 3.3 员工信息变更（三种方式）

> 操作角色：前台业务员

| 变更类型 | 入口按钮 | 是否需审核 | 影响范围 |
|---|---|---|---|
| **基本信息变更**（不审核） | 弹窗"基本信息变更" | 否，直接改 | AC01 直改 + TC90 28 字段同步 |
| **姓名/身份证变更**（送审'25'） | 弹窗"变更基本信息" | 是（tdbd 审核） | TC92 记录前后值 → 审核后 4 表同步 |
| **合同/参保变更**（送审'21'） | 弹窗"变更合同信息" | 是（tdbd 审核） | TC92 记录前后值 → 审核后 141 列刷新 |

**基本信息直改操作**：
1. 菜单 → **员工管理** → **员工信息变更申请**
2. 查询到员工 → 点击 **【基本信息变更】**
3. 修改允许变更的字段（身份证/姓名只读）→ 保存 → **立即生效**

**姓名/身份证变更操作**：
1. 查询到员工 → 点击 **【变更基本信息】**
2. 系统展示变更前/后对照表
3. 输入新姓名/新身份证（系统自动校验身份证格式和查重）
4. 保存 → 生成审核单（'25' 类型）→ 等待审核
5. 审核通过后 → 4 表同步新姓名/新身份证

**合同/参保变更操作**：
1. 查询到员工 → 点击 **【变更合同信息(审核)】**
2. 页面显示几十组字段，每组有"变更前"和"变更后"两列
3. 修改需要变更的字段的"变更后"值
4. 提交 → 生成审核单（'21' 类型）→ 等待审核
5. ⚠ 注意：即使没有实际修改任何字段，也可以提交（系统不拦截）

### 3.4 员工调转（两种调转）

**同一结算单元内调转二级单位/部门**：
- 菜单 → 员工管理 → **员工调转二级单位/部门申请**
- 选一级单位 → 列出该单位生效员工 → 选择目标二级单位 → 确认转入
- 存储过程一步生效（无审核流）
- ⚠ 该功能因包编译失败当前不可用

**跨结算单元调转**：
- 菜单 → 员工管理 → **员工变更结算单元调转**
- 左栏显示"调转前"员工列表，右栏显示"调转后"
- 勾选员工从左栏"调转>>"到右栏 → 点击 **【提交到审核】**
- 生成审核单（'26' 类型）→ 审核通过后 → 员工合同在新结算单元生效

### 3.5 错误数据删除

- 菜单 → 员工管理 → 员工信息审核页面
- 选中错误员工 → 点击 **【错误数据删除】**
- 系统物理删除该员工的所有数据（TC90/TC90_LIST/TC93/TC08/AA97 等）
- ⚠ 已生成工资的员工无法删除
- TB91 审核单保留（作为历史记录）

## 第四章 社保/医保/公积金报增报减操作

### 4.1 社保报增（新参保）

> 操作角色：社保经办员

**前提**：员工已通过审核（ATB90R='3'，已生效）

1. 菜单 → **员工异动/补退费管理** → **员工社保报增申请**
2. 选择**险金户头**（从下拉列表选择，如"吉林省彩虹人才开发咨询服务有限公司(汪清)"）
3. 选择**区划**（从树形列表选择）
4. 系统自动列出该户头下待报增的员工列表
5. 勾选要报增的员工 → 点击 **【报增】** 按钮
   - 系统调用过程逐人生成社保报增明细（TC9W 表）
   - 如当月数据已回盘，系统提示"当月数据已经回盘，不能重新生成"
6. 生成后可查看报增名单，核对无误

### 4.2 社保报减（停保）

1. 菜单 → **员工异动/补退费管理** → **员工社保报减申请**
2. 查询到要报减的员工
3. 页面上操作报减 → 生成报减明细行（atc9w1='3'）
4. 提交审核 → 审核通过后生效

### 4.3 市医保/省医保/公积金报增报减

操作方式与社保报增/报减**完全同构**，只是入口页面和目标明细表不同：

| 险种 | 报增页面 | 报减页面 | 明细表 |
|---|---|---|---|
| 社保 | 员工社保报增申请 | 员工社保报减申请 | TC9W |
| 市医保 | 员工市医保报增申请 | 员工市医保报减申请 | TC9W1 |
| 省医保 | 员工省医保报增申请 | 员工省医保报减申请 | TC9W2 |
| 公积金 | 员工公积金报增申请 | 员工公积金报减申请 | — |
| 省工伤 | 省工伤报增申请 | 省工伤报减申请 | — |

### 4.4 社保异动报盘回盘

> 操作角色：社保经办员

**报盘**：将本月社保增减变动导出为社保局要求的文件格式
1. 菜单 → **员工异动/补退费管理** → **社保异动报盘回盘**
2. 选择险金户头和年月
3. 系统生成报盘文件 → 导出提交给社保局

**回盘**：社保局处理后返回结果文件，导入系统确认
1. 导入社保局返回的结果文件
2. 系统根据回盘结果更新员工社保状态（ATC9W8: '1'已生成 → '4'已回盘）
3. 回盘后当月数据锁定，不可重新生成

## 第五章 工资管理操作

### 5.1 工资项目设置

> 操作角色：工资管理员

1. 菜单 → **派遣费用管理** → **工资项目细项设置**
2. 选择单位 → 设置该单位员工的工资项目（基本工资、岗位工资、绩效等）
3. 每个项目有：项目名称、金额、排序号

### 5.2 工资导入

> 操作角色：工资管理员

1. 菜单 → **派遣费用管理** → **导入工资信息维护**
2. 下载工资导入模板（Excel 文件）
3. 填写员工工资数据 → 上传导入
4. 系统解析 Excel → 数据写入暂存表（TC93_BP1）
5. 菜单 → **派遣费用管理** → **导入工资信息审核**
6. 审核通过后 → 工资数据正式入库（TC93 表）

### 5.3 工资发放

1. 菜单 → **派遣费用管理** → 相关功能
2. 生成应发工资数据
3. 核对无误后确认发放

### 5.4 应发工资花名册核对

1. 菜单 → **员工管理** → **应发工资花名册核对**
2. 选择结算单元和年月 → 系统调用过程生成花名册
3. 核对花名册数据与实际工资是否一致

## 第六章 参保地/结算单元变更操作

### 6.1 参保地变更（医保）

> 适用场景：员工的医保参保地需要从一个城市变更到另一个城市

1. 菜单 → **员工异动/补退费管理** → **医保参保地变更**
2. 查询到员工 → 选择新参保地（从区划树选择）
3. 系统校验：
   - 新参保地必须存在于行政区划字典
   - 员工必须参加了医保（AAA402='1'）
   - 员工医保必须是"参保成功"状态（ATC90PA='0'）
   - 当月该结算单元未做费用结算
4. 确认变更 → 系统自动：
   - 创建新合同行（新参保地，生效状态'3'）
   - 旧合同行终止（'5'，报减年月回填）
   - 险种间互斥镜像更新

### 6.2 结算单元调转

> 适用场景：员工从一个结算单元调到另一个结算单元

1. 菜单 → **员工管理** → **员工变更结算单元调转**
2. 左栏显示当前结算单元员工 → 勾选 → "调转>>" 到右栏
3. 点击 **【提交到审核】** → 生成审核单（'26' 类型）
4. 系统为每个调转员工创建 TC90_LIST 克隆行（新单元字段覆盖，ATB90R='2'/AAE100='0'）
5. 审核通过后 → 克隆行生效（ATB90R='3'/AAE100='1'）→ 员工在新结算单元生效

## 第七章 系统管理操作

### 7.1 代码信息维护（字典管理）

> 操作角色：系统管理员

1. 菜单 → **综合信息管理** → **系统参数信息管理** → **代码信息维护**
2. 页面显示代码字典列表（AA10 表）
3. **新增代码**：填写分类（AAA100，≤10字符）、码值（AAA102）、码值含义（AAA103）
4. **修改代码**：选中行 → 修改 → 保存
5. **删除代码**：选中行 → 删除
6. ⚠ 字典数据是全系统基础，修改前确认无业务依赖

### 7.2 行政区划维护

1. 菜单 → **综合信息管理** → **行政区划维护**
2. 树形结构显示行政区划（AA12 表）
3. 新增：填写区划代码、名称、父级区划
4. 行政区划用于参保地选择、区划筛选等

### 7.3 综合参数维护

1. 菜单 → **综合信息管理** → **综合参数信息维护**
2. 维护系统级参数（AA01 表）
3. 每个参数有：业务线代码、参数代码、参数名、参数值

### 7.4 社保参数维护

1. 菜单 → **人才派遣管理** → **参数管理** → **社保参数维护**
2. 维护公积金比例表（AA94）
3. 按险种和参保地设置缴费比例

### 7.5 异动期设置

1. 菜单 → **人才派遣管理** → **参数管理** → **社保报减异动期设置**
2. 设置每月异动日（如 18 号）
3. 此设置影响新增员工时社保报增年月的计算：
   - 当前日期 ≤ 异动日 → 当月报增
   - 当前日期 > 异动日 → 下月报增

## 第八章 按业务场景速查

### 场景：新单位签约

```
1. 单位协议管理 → 新签单位协议申请 → 填写协议信息 → 暂存 → 提交
2. 单位协议管理 → 协议信息审核 → 审核通过
3. 基本信息管理 → 单位基本信息维护 → 完善单位详细信息
4. 参数管理 → 险金户信息维护 → 确认险金户头已设置
```

### 场景：新员工入职（全流程）

```
1. 员工管理 → 新增员工信息申请 → 录入员工信息 → 暂存
2. 员工管理 → 新增员工信息申请 → 提交到审核
3. 员工管理 → 员工信息审核 → 审核通过（ATB90R='3'）
4. 员工异动 → 员工社保报增申请 → 选择户头 → 报增
5. 员工异动 → 员工市医保报增申请 → 报增（如需）
6. 员工异动 → 社保异动报盘回盘 → 报盘给社保局
7. 派遣费用管理 → 导入工资信息维护 → 导入首月工资
8. 派遣费用管理 → 导入工资信息审核 → 审核通过
```

### 场景：员工离职（全流程）

```
1. 员工管理 → 合同终止或解除申请 → 发起终止 → 提交
2. 员工管理 → 员工信息审核 → 终止审核通过（ATB90R='5'）
3. 员工异动 → 员工社保报减申请 → 报减当月社保
4. 员工异动 → 社保异动报盘回盘 → 报盘回盘
5. 员工管理 → 劳动合同终止员工查询 → 打印解除证明
6. 员工管理 → 审核信息处理 → 处理退费（如有）
```

## 第九章 系统限制与注意事项

### 9.1 不能做的事

| 事项 | 原因 |
|---|---|
| 同月重复报增 | 系统检测已回盘数据，拒绝重新生成 |
| 删除已发工资员工 | PRC_删除员工拒绝（防误删） |
| 远期月份(2099等)报增 | 过程内部桶展开无界膨胀 |
| 跨页借用其他页面的审核功能 | 交互按页面隔离 |

### 9.2 容易犯错的地方

| 易错点 | 后果 | 正确做法 |
|---|---|---|
| 暂存后忘记提交到审核 | 员工一直不生效 | 暂存后及时提交 |
| 终止申请后以为员工还在职 | 主记录已失效 | 确认终止后再安排工作 |
| 修改时只发关键字段 | 其他字段被清空 | **必须整行提交** |
| 填写超长内容 | 报"数据过长" | 注意字段长度限制 |
| 在远期月份操作 | 可能引发大量数据生成 | 只用相邻月份测试 |

### 9.3 已知的系统缺陷（使用时注意）

| 缺陷 | 影响页面 | 表现 |
|---|---|---|
| 员工调转二级单位不可用 | tdbe | 包编译失败，点击即报错 |
| 撤销解除不可用 | tdbq | 包编译失败 |
| 合同导入提交不可用 | tdbp | 包编译失败 |
| 历史合同查看按钮无效 | tdbb/tdbo | 目标页面不存在 |
| 问题登记后无法审核 | xaha→xahb | 序列未配号导致 |
| 多合同只更新第一份 | tdbc jbxx | 代码 bug(get(0)) |
| 零变更可提交审核 | tdbc htbg | 无变更拦截缺失 |
