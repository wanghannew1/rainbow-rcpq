## 方法论

1. **清单解析**: 从 `DELETED_FILES_DETAIL.md` 提取全部 `- /path` 行, 映射为 `src/main/webapp/` 下的相对路径。
2. **排除项**: 所有包含 `webdesign/ext-1.1.1` 的路径 (386 个) 已确认是工作流流程设计器核心依赖, 不参与核查。
3. **搜索范围**: `src/main/webapp/` 下 `*.jsp / *.js / *.css / *.html / *.xml / *.java / *.properties / *.tld / *.tag` 文件; XSL 备份组额外扫描 `src/main/java/*.java` 与 `src/main/resources/*.xml`。**不搜索任何 JAR 文件**。
4. **引用识别**: 对每个范围文件逐行提取路径型 token (含 `url(...)`、`<script src>`、`getDS("...")`、`WEB_APP_NAME + "/..."` 等形态), 解析相对路径 (`../`、`pages/`→`lemis/pages`、`ts/`→webapp 根) 后与待删除路径**精确比对**。
5. **判定规则**:
   - **🔴 有引用**: 存在解析后与待删除路径完全一致的引用 (强证据)。
   - **⚠️ 需复核**: 存在目录级动态引用 (如 `request.getContextPath()+"/.../images"` 拼接文件名), 或裸 basename / DataStore 名部分匹配且磁盘上无同名保留副本可承接。
   - **✅ SAFE**: 无任何引用, 或所有部分匹配均指向其他保留文件 (路径解析后与已删文件不同, 或同名保留副本仍存在)。
   - 外部 URL (首段为域名, 如 `java.sun.com/...`) 与 JS 变量 (如裸 `ts`) 不构成引用。
6. **自引用排除**: 待删除文件内部对彼此的引用不计入结果。
