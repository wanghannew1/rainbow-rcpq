**用途**：续签合同到期自动生效：扫描待生效续签合同（`TC90 WHERE AAE100='0' AND ATB90R='3' AND ATC90F='2'`），到期（AAE002<=今天）则终止旧合同（ATB90R='5'、AAE003=前月、AAE013+=';续签终止'）并把新续签合同置有效（AAE100='1'），逐条写 SYS_SCHEDULE_INFO 执行日志（TYPE 1 成功/2 失败+SQLERRM）。

**过程清单**：仅 `PRC_CHECK_TC90(PRM_CODE OUT NUMBER)`（body:3，50 行全包）。注意：**过程体从不给 PRM_CODE 赋失败值**（入口赋 1，异常分支 `WHEN OTHERS THEN NULL` 吞掉一切，且**无 COMMIT**——依赖调用方事务/自动提交）。

**调用方**：
- Java：`src/main/java/com/neusoft/lemis/scheduler/job/doUpdateTc90.java:37` → `call PKG_JOB.PRC_CHECK_TC90(?)`（registerOutParameter NUMBER）。
- 调度注册：`src/main/webapp/WEB-INF/conf/lemis/lemis-schedule.xml:20-29`（JobDetailBean，jobClass=doUpdateTc90，scheduleId=doUpdateTc90）；Quartz JobStoreTX + QRTZ_ 表（unieap-schedular.properties:23-27），cron 触发器在库内 QRTZ_ 表/调度管理页配置，代码库无 cron 表达式。
- 前端/包间：零调用。

**触碰表**：TC90（读+两处 UPDATE）、SYS_SCHEDULE_INFO（INSERT）。

**状态**：**活跃**（Quartz 驱动；0.60 库每天 03:39-03:47 的 7 条 procedureService 裸异常疑与备份重启窗口相撞，见 数据库状态字段与关联关系梳理.md §环境拓扑）。异常吞掉 + 日志表是唯一的可观测面。

**重写建议**：改 Spring `@Scheduled`/任务表 + 一条带子查询的 UPDATE（或两条），把 `WHEN OTHERS THEN NULL` 换成显式日志与告警；保留 SYS_SCHEDULE_INFO 或改应用日志表；**必须显式提交**。50 行逻辑一句话说清，重写成本最低。

## 9. PKG_SYNCHR_UPDATE —— AC01/AB01 全库同步（外部系统入口嫌疑，重点排查结论）

**用途**（包头注释原文）："修改 AC01 或 AB01 基本信息中某些字段值时，同步更新所有业务表相关基本信息字段，**可以提供给社险系统调用**，从而实现自动更新劳动就业基本信息的目的"。作者 linwj/chenxj 改造，2001 年。

**过程清单**（3 个 + 局部 2，body 行号）：

| 过程 | 入参 | OUT | 一句话（body:） |
|---|---|---|---|
| FUNC_GET_TOKEN(:19) / PRC_K_获取输入参数(:44) | '\|'分串 | — | 局部工具（与 PKG_基本信息 同源复制） |
| PRC_AC01_UPDATE(:65) | AAC001,列名串'AAB004\|AAE005\|',值串'湘华宾馆\|尹能静\|123456\|' | code,msg | **动态 SQL**：游标扫 `USER_TAB_COLUMNS×TAB` 找所有含 AAC001 列的表（排除 BIN$ 回收站），逐表 COUNT 命中→按 USER_TAB_COLUMNS 类型拼 `UPDATE <表> SET <列>=… WHERE AAC001=…` EXECUTE IMMEDIATE，显式排除 AC01/AC06 本体；结束 COMMIT |
| PRC_AB01_UPDATE(:198) | AAB001,列串,值串 | code,msg | 同上，AAB001 版，排除 AB01/AB06 |
| PRC_变更结算单元名称(:330) | ATB930,新名称 | code,msg | UPDATE TB93.ATB931 + TC93(ATB931,AAB004) + TC90(AAB004,ATC90X)（AB01/TB90 两行在注释里） |

**调用方（重点排查结论）**：
- **Java：零调用**（含 `PKG_\u` unicode 转义全量 grep，仅命中 PKG_基本信息/人才派遣/职介业务，无 SYNCHR_UPDATE）。
- 前端：仅 1 处——`td/a/a/tdaa_dialog_tb93.js:170 PRC_变更结算单元名称`（单位登记页"变更结算单元名称"弹窗，活菜单）。
- 包间：零调用（pkg_all 全 dumps 无 PKG_SYNCHR_UPDATE.* 业务调用，仅自引 DEF_OK/DEF_ERR）。
- **AC01/AB01 两个同步过程在本仓库内零调用方**，与其"提供给社险系统调用"的自述一致：确认为**外部系统直连数据库调用的预留接口**（调用痕迹不落应用日志，0.60 生产历史检索不到属预期）。迁移时按"外部契约"对待，不可静默删除。

**触碰表**：动态——任何含 AAC001/AAB001 列的用户表（USER_TAB_COLUMNS×TAB 运行时决定）；静态写 TB93、TC93、TC90。

**状态**：**半死**。变更结算单元名称活跃；两个同步过程无内部调用方，属对外接口，且设计危险（全库扫表 + 字符串拼 SQL + 无字段白名单 + 列名/值未做注入消毒；调用方传 `'A|)` 或类似串即可注入；错值直写全库）。

**重写建议**：**接口化+白名单化**。① PRC_变更结算单元名称 并入单位服务；② PRC_AC01/AB01_UPDATE 若确需保留对外能力，改成显式字段白名单（可同步字段清单硬编码/配置表）+ REST 服务，绝不能带"扫全库表"逻辑进 PG；③ 重写前与业务确认社险对接是否还在用（在 0.60 上开审计或问接口方），拿到证据再决定废弃或保留。
