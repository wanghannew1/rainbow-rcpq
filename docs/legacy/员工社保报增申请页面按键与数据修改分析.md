# 员工社保报增申请页面：按键功能与数据库字段级修改分析

> 页面: `/lemis/pages/td/c/a/tdca_cont.jsp`（菜单：员工社保报增申请）
> 主表: `TC9W`（社保报增/续保/报减名单）｜底账: `TC90`（人才派遣员工合同+参保信息，合同与参保两类信息同表）
> 分析方法: 全部按键处理函数（`tdca_cont.js`）静态分析 + 本地 Tomcat(8090) 独立部署 + HTTP 报文重放实测，
> 以测试年月 `202612`/`209901`、经办人 `zhanghsh` 驱动真实执行，JDBC 前后逐字段 diff 验证，测后已清理（两测试月 0 残留）。
> 分析日期: 2026-11-13

## 0. 背景状态字段（先读这个）

| 字段 | 含义 | 值域 |
|---|---|---|
| `TC9W.ATC9W8` | 审核状态 | `1` 暂存(生成后初始) → `3` 已提交确认 → `4` 已回盘(终态) |
| `TC9W.ATC9W2` | 申报状态 | `0` 未申报 / `1` 已申报（"已申报"按钮置位） |
| `TC9W.ATC9W1` | 名单类别 | `1` 报增（本页面查询固定条件）/ `2` 续保相关 / `3` 报减 |
| `TC9W.AAA90X` | 申报结果 | 生成时默认 `'90'`（失败），回盘后更新 |
| `TC90.ATC90P` | 参保暂缓/异议标记 | 转入按钮清空 |

## 2. 写库按键的字段级明细

### 2.1 生成报增名单（唯一的大写库入口）

**调用链**: `doCreate` → 交互 `REQ-UTIL-procedureService-Q` → `ProcedureService.query` → JDBC `CallableStatement`
→ `PKG_保险人员增减.PRC_社保人员增减(户头AAA030, 年月AAE002, '1'报增, 经办人AAE011, 区划AAA100)`
（`appCode=-1` 时 `ProcedureService` 抛 `LemisBusinessException` → `BusinessDispatcher` 的 `PROPAGATION_REQUIRED` 事务整体回滚）

**过程内部步骤（2026-11-13 实测验证）**:

1. **守卫**: 存在 `ATC9W8='4'` 的当月行 → 拒绝（"当月数据已经回盘，不能重新生成"）
2. **可重生成**: `DELETE FROM TC9W WHERE ATC9W1 IN('1','2') AND ATC9W8='1' AND ATC9W2='0' AND AAA100=区划 AND AAA030=户头 AND AAE002=年月`（只删未申报的暂存行，`'3'/'4'` 状态行永不触碰）
3. `UPDATE TC06 SET KEY1=NULL WHERE AAE002=年月`
4. **三路数据源**逐人 `INSERT INTO TC9W`（主键冲突忽略=幂等）:
   - TC06 特殊变动（`AE100='1'` 且 `ATC061='03'` 或 `('06','2')`/`('07','2')`）→ 附带 `UPDATE TC90 SET AAA301=?, AAA304=? WHERE ATC900=?`
   - TC90_ZJBG 变更引起的增加
   - 主查询 TC90×AB01（新参保 `ATB90R='3'` / 离职补缴 `ATB90R='5' AND AAA204>年月`、`AAA100=区划`、未报盘、`AAA401='1'`、`AAE00P IN('1','5','7')` 等）
   - **跨年补缴桶写 TC08**：人员参保起始年早于目标年时，按年度桶展开（`KSNY~JSNY` 月区间），逐桶 `INSERT INTO TC08`——**这是"跨年补缴名单"弹窗的数据来源**（同年内补缴不产生 TC08 行，实测 202612 生成时 TC08 零写入）
5. **收尾**: `UPDATE TC90_YY SET CBSIGN='9' WHERE SAFESIGN='1' AND ATC900 IN (离职异议人员)`（幂等，实测 144 行早已全为 '9' 无变化）

**TC08 跨年补缴明细行字段实测样本**:

| 字段 | 值/来源 |
|---|---|
| `ATC080` 主键流水、`BAZ001/BAZ002` 序列 | |
| `AAE002` | **目标年月**（生成时传参，如 209901） |
| `AAE000` | 补缴年度桶（如 2026） |
| `KSNY`/`JSNY` | 该桶补缴起止月（如 202609~202612） |
| `AAA000` | 补缴类别（实测出现 1/2/3 三类并行动） |
| `AAA300` | 缴费工资(2230) |
| `ATC900`/`ATB900`/`AAC001` | 底账/合同/人员关联键 |
| `ATB930`/`ATB931`、`AAB001/004` | 合同编号、单位（双份冗余） |
| `AAA030`/`AAA031`、`AAA020`/`AAA021` | 户头、区划（均带名称冗余） |
| `AAE011='001'`、`AAE019='业务员基础版v1.0'` | **过程内硬编码的经办章**，非登录用户 |
| `AAE017`/`AAE020`/`AAE022`、`AAE036` | 机构戳 + SYSDATE |

**插入行字段实测样本（202612 月，66 个非空字段，关键项）**:

| 字段组 | 字段 → 值来源 |
|---|---|
| 主键/序号 | `ATC9W0`=流水(1392490)，`BAZ001`/`BAZ002`=序列值 |
| 归属 | `AAA030`=户头, `AAA031`=户头名称, `AAA100`=区划, `AAA101`=市, `AAB001`=单位号, `AAB004`=单位名, `ATC900`/`ATB900`/`AAC001`=底账关联键 |
| 人员 | `AAC002`证件号, `AAC003`姓名, `ABP001`证件类型, `ABP002`出生(`VARCHAR`), `ABP003/004`民族性别, `ABP006/007`工人工种身份, `ABP107`户籍(DECODE 非农/农业) |
| 参保 | `ABP005/008/013/015/101/108/109`=各类日期(全部 `VARCHAR`), `ABP012/102`工资, `ABP014`变更原因(6201 人员续保), `ATC904`=起始年月, `AAE003`, `IFSYB`省医保(判断 AAA402+AAA110), `ZYNUM` |
| 状态 | **`ATC9W8='1'`(暂存), `ATC9W2='0'(未申报), ATC9W1='1'(报增), AAA90X='90'(申报结果默认失败), ABPZZZ='0'`** |
| 经办 | `AAE011`经办人, `AAE017`机构, `AAE019`经办人名, `AAE020`机构名, `AAE022`区划, `AAE036`=SYSDATE 时间戳 |

实测: 户头=1/年月=202612 生成 80 行，全部 `1/0/1` 状态组合；TC06、TC90_YY、TC90 主数据零意外变化。

### 2.2 已申报 / 未申报（实测字段级 diff）

调用链: 勾选行 → 客户端置值 → 交互 `REQ-f9192e418a4e4b85978d45b03f3685a7` → `tc9wStore_grid.save()` → PojoUtil 实体构造 → Hibernate **整行 UPDATE**。
注意：因为整行重写，**前端提交的行数据必须完整**——只发主键会把其余字段清空（服务端 `getValueObj`/`setProperty` 按提交值覆盖）。

| 按键 | 实测数据库变化（仅此 2 字段） |
|---|---|
| 已申报 | `ATC9W2: '0'→'1'`；`BAZ002: 10199905→10287537`（操作序号盖章） |
| 未申报 | `ATC9W2: '1'→'0'`；`BAZ002: 10287537→10322399` |

其余 60+ 字段（含六经字段 `AAE011/017/019/020/022/036`）不变——`InteractionParameterUtil.initConstants`
对修改行只盖 `BAZ002`（取自 `SEQ_SYS_BAZ002` 请求级预取池），六个经办字段仅新增行填充。

### 2.3 转入（未实测，静态分析）

`doIn`: 确认框 → 取 grid_2 勾选行 `ATC900` → `tc90Store` 查询该行 → 客户端置 `atc90p=''` → `tc90Store.save()`
→ **`UPDATE TC90 SET ATC90P=NULL`**（清除参保暂缓/异议标记，人员进入正常参保）。
关联过程 `PKG_保险人员增减.PRC_异议处理`（SYS_ERR_LOG 中 452+425+233 次业务性拒绝记录，说明该链路活跃）。
空手点击仅提示"请选择一条数据!"，无数据库操作。

### 2.4 跨年补缴名单弹窗深入（`tdca_dialog_knbj.jsp/js`，实测）

弹窗本体**纯只读**，三个按键全部无写库行为：

| 弹窗按键 | 处理函数 | 行为 |
|---|---|---|
| 查询 | `doQuery` | SELECT TC08（只读，实测） |
| 重置 | `doReset` | 纯前端（form.reset + 行集 reset） |
| 关闭 | `doClose` | 纯前端；关闭后父页面 `onComplete → queryTc93()` 刷新 TC93 网格（只读） |

**查询逻辑**: 条件硬编码 `aaa000='1' and aaa030=户头 and aaa020=区划 and aae002=年月`（注意 TC08 的区划字段名是 `AAA020` 不是 `AAA100`），`ORDER BY atc900 DESC`，交互 `REQ-e6dbc1dc4b60410b8c1d3ea09dee6fec`。网格 9 列（姓名/证件号/AAE000/起月/止月/AAA300/合同/户头名/单位名，均为码表渲染），网格自带 `export="1"` 导出（只读）。

**数据闭环**: TC08 行不是这个页面产生的——它是**生成报增名单**过程为跨年补缴人员按年度桶写入的（见 2.1 第 4 步）。所以该弹窗展示的是"生成动作沉淀的跨年补缴明细"，与 TC9W 名单同源同时点。

## 5. 已知坑位备忘

1. **209901 类远期年月严禁用于生成测试**——不只是"跑得慢"：跨年补缴桶会按年展开（每人数百个月桶），真实写入海量 TC08/TC9W 行（本次事故 ~1.6 万行，跑了 14 分钟，且客户端断开后 Oracle 侧过程会继续执行到结束）。测试请用相邻月。
2. **清理生成类测试数据必须同时清 TC9W 和 TC08**——TC08 补缴明细是过程暗写的，容易漏（本次就漏了一轮）。
2. **保存必须整行提交**——只发主键+变更字段会清空行内其余字段（PojoUtil 实体全量覆盖语义）。
3. `PRC_社保增减确认` 缺失 + "确认可报盘"隐藏——历史遗留，见正文第 1 节；勿在兄弟页面（`td/c/ad`、`td/c/ae` 未隐藏该按钮）点击。
4. 凌晨备份重启库后首访的 Broken pipe 已由 DBCP `testOnBorrow` 修复（issue #2），生成/保存链路不受影响。
