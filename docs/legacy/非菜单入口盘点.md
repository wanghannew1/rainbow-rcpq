## 一、调度任务 — 唯一活跃业务写路径 ⚠

**配置源: `SYS_SCHEDULE`(仅 1 行, `switch=1` 生效)**

| 项 | 值 |
|---|---|
| ID / 名称 | doupdatetc90 / **刷新合同状态** |
| cron | `0 00 01 ? * *`(每晚 01:00) |
| 执行链 | SchedulerManagerImpl(`select … from sys_schedule where switch=1`) → ProcedureJob → **`call PKG_JOB.PRC_CHECK_TC90(?)`** |
| 运行记录 | LOG_SCHEDULE 2595 次(2018-03-02 起恒 01:00, 全部 Success) |

**PRC_CHECK_TC90 语义**(pkg 源码, 49 行): 扫 `TC90 WHERE AAE100='0' AND ATB90R='3' AND ATC90F='2'`,
`AAE002<=当日` 时: 终止同单位同人的旧有效合同(`AAE100='0', ATB90R='5', AAE013+=';续签终止'`)
→ 新合同置 `AAE100='1'` → 写 SYS_SCHEDULE_INFO。**外层 `WHEN OTHERS THEN NULL` 静默吞错**。

⚠ **重写必须带上这个 cron**(菜单里没有任何入口指向它);
⚠ **测试夹具注意**: TC90 行若 `ATB90R='3'+ATC90F='2'` 且 `AAE002<=今天`, 凌晨 01:00 会被夜刷改状态。

**未投活的调度**: UniEAP 平台级 GenerateReportJob(~83min)/BackupJob(~7d) 已注册但业务无关;
两个 20:45 cronTrigger 定义了却没挂进 triggers 列表。QRTZ_* 12 表全 0 行(RAMJobStore,
事实配置源是 SYS_SCHEDULE 表)。
