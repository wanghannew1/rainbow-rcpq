> 代码字典(AA10)、行政区划(AA12)、综合参数(AA01)、公积金比例(AA94)、单位信息(AB01)、险金户(AA03)。

## 一、表型分类与元数据约束画像

| 表 | 类型 | PK 策略 | hbm 非空 | ds 元数据非空 | 宽松度 |
|---|---|---|---|---|---|
| AA10 代码字典 | 复合 PK | 手工(AAA100+AAA102) | — | 3 列 | 中 |
| AA12 行政区划 | 单 PK | 手工(ID) | — | — | 宽松 |
| AA01 综合参数 | 单 PK | 序列(SEQ_AA01_AAA010) | 8 列 | 4 列 | hbm 严 |
| AA94 公积金比例 | 单 PK | 序列(SEQ_AA94_AAA940) | 1 列(PK) | 1 列 | 宽松 |

**规律: 约束来源不统一**(AA01 hbm 严于 ds、AB01 ds 严于 hbm、AA94 双宽松)。
重写应统一到一种约束来源(DDL 级 NOT NULL + 应用层 schema 验证)。

## 二、通用 CRUD 通道(v3 模板)

### 插入
- 交互: 页面自定义(如 REQ-xaad_cont-aa10Store_Save / REQ-xaab_cont-aa12Store-M)
- 载荷: 完整行(含 hbm ∪ ds 非空全集) + `_t:1`
- PK: 序列表不传(服务端配号) / 手工表传内容标记值

### 修改
- 交互: 同页 Save 或 Update
- 载荷: 完整行 + `_t:3` + `_o:{变更字段:旧值}`

### 删除
- 交互: 页面 Delete 交互
- 载荷: 完整行入 `rowSet.delete` 数组
- ⚠ **字典页删除通道家族怪癖**: 程序化 delete 数组报 `primary is not a JSONArray`
  (需浏览器级完整 grid rowSet; 两页同病=系统性模式)

## 三、各表要点

### AA10 代码字典
- 用途: 全系统状态码义查(列名→码值→含义)
- AAA100(分类)限 10 字符(ORA-12899 实测)
- 基线 7341 行(2026-11-14 盘点=重导后精确一致)
- 列语义差异大: aac017=婚姻状况(非区划)、aac033=健康状况(非电话)——**以 ds label 为准**

### AA12 行政区划
- 树形结构(ID/PARENTID/HASCHILD)
- ID 形如 `220100000000`(12 位区划码)，LABEL 为名称
- tdcbg 参保地变更/tdbl 结算单元调转等的数据依赖

### AA01 综合参数
- aaa001=参数代码(200 字符，注释"交互代码"!——可能用于系统参数→交互映射)
- aaa002=参数名、aaa004/aaa005=参数值
- 生产仅 9 行 = 近零使用的摆设功能

### AA94 公积金比例
- aaa941=险种、aaa100/101=参保地、aaa942-947=五险比例、atb90s=公积金比例
- 183 行(修正记忆"09/10 零行"=特定险种子集非全表)
- tdgb 页面 save → AA94 直插(唯一经过实弹的 SERVICE 参数页)

### AB01 单位信息
- 核心主数据(生产数百行)
- ds 元数据必填 7 列(aab004/aab301/aab019/aab020/aae006/bae011/aab00a)
- **aab019=单位性质 限 3 字符**(ORA-12899 实测)
- aab301=所在地区划 12 字符
- 与 TC90(员工合同)、TC90_LIST(合同明细)、AA03(险金户)形成核心关联

### AA03 险金户
- 全库仅 4 行(核心参保流程前置主数据)
- AAA030=户头 PK(NUMBER 无格式约束)、AAA031=户头名、AAA032=社保账号、AAA033=公积金账号
- **新户头即插即用于全部报增/确认过程**(AAA030 无格式/存在性校验外的限制)

## 四、重写注意事项

1. 字典/参数/比例/户头 = 参保流程的**前置主数据**——CRUD 应有完整校验
2. 约束来源统一(勿两套标准并存)
3. 树形表(AA12)的 PARENTID/HASCHILD 结构保留
4. AA10 复合主键(AAA100+AAA102)的查询模式 = 按分类批量取码值
5. 删除通道(程序化)需重新设计——遗产实现有家族性解析缺陷
