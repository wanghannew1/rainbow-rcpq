# 重写功能规格 03 — 遗产缺陷清单与防护规则

> 写入重放战役实测发现的全部遗产系统缺陷(12+ 项)。
> 每条标注缺陷类型/实弹证据/重写防护规则。
> **核心原则: 重写时逐条对照，确保不重蹈覆辙。**

## A. 功能性缺陷(用户可见)

### A1. 平均工资除零崩溃
- **位置**: PKG_人才派遣公共.PRC_计算平均工资
- **症状**: 零工资覆盖人员 → ORA-01476 除数为 0 → 500 系统错误弹窗
- **根因**: 无工资行时除法分母为 0，无"查无此人"前置校验
- **重写规则**: 查无记录 → 返回结构化提示(200+errMsg)，不抛数学异常

### A2. 幽灵过程(页面引用不存在的过程)
- **位置**: tdcad/tdcbe 页 JS 引用 `PRC_医保增减确认`; tdba 引用 `PRC_GET_MONEY_JL`
- **症状**: 点击 → PLS-00302 组件不存在 → 500
- **根因**: JS 与包 spec 脱节(开发遗弃/重命名未同步)
- **重写规则**: API 端点必须从 package spec 生成，编译期即校验

### A3. 跨页坏引用
- **位置**: tdcaw_cont.jsp 借用 tdbp_cont 的 `REQ-tdbp_cont-tb93Store-Q`
- **症状**: 查询即 500
- **重写规则**: 页面→交互路由必须编译期绑定，禁止跨页借用

### A4. hbm 配置矛盾(AA92)
- **位置**: AA92.hbm.xml String 主键 + sequence 生成器
- **症状**: 所有 INSERT → "Unknown integral data type for ids"
- **根因**: AgileKit 自动生成 hbm 时列类型与生成器不匹配
- **重写规则**: ORM 映射 PK 类型必须与生成器兼容(序列→Long/Integer)
- **状态**: **已修复**(移除生成器改人工赋值，8091 部署+实测 ✓)

### A5. 问题管理平台 qid=null
- **位置**: xaha 登记交互 U 型 generic update
- **症状**: 登记产出 qid=null → 审核无法定位 → 整条功能链报废
- **根因**: U 交互走 assigned-id 路径，序列生成器未触发
- **重写规则**: 所有 PK 由序列赋值且 NOT NULL 约束强制执行

## B. 数据一致性缺陷

### B1. 错误日志二次掩盖
- **症状**: -30010 记录日志错误(SYS_ERR_LOG INSERT 失败) → 真实错误被掩盖
- **根因**: 错误日志写入也在同一事务中，失败时连错误信息都无法保存
- **重写规则**: 错误日志使用独立事务(REQUIRES_NEW)，失败不阻塞主流程

### B2. 提交未审即失效
- **位置**: tdbb 终止申请
- **症状**: AAE100 即时置 '0'，若审核不通过需人工恢复
- **重写规则**: 状态变更延迟到审核通过时，或使用独立"审批中"状态

### B3. 删除后 TB91 留存
- **位置**: PRC_删除员工
- **症状**: TC90 删净但 TB91 审核单留存(qstate='3')
- **语义**: 非纯 bug——TB91 为历史档案；但缺清理标记导致区分困难
- **重写规则**: 审核单增加"关联员工已删除"标记，或外键级联标记

### B4. 零外键架构
- **症状**: 裸员工(无 TC90_LIST)可通过终止审核；TC9W1 无对应 TC90 行也能操作
- **重写规则**: 核心外键约束至少在应用层强制(人员→合同→明细三层完整性)

## C. UX 缺陷(错误呈现)

### C1. 500 顶替结构化错误
- **症状**: 过程报错(title-less LemisException) → PojoAction:83 JSON NPE → 500 HTML
- **根因**: 框架 setTitle(null) 时 JSON 库抛 JSONException
- **重写规则**: 所有业务错误返回结构化 JSON(200 + appCode + errMsg)，禁止 500

### C2. 静默无操作
- **症状**: 保存 200 但数据未变(_t 缺失或 isModify 不认可)
- **重写规则**: 保存操作必须返回实际影响行数，零行时警告

### C3. recordCount 说谎
- **症状**: 响应 recordCount=0 但 rowSet.primary 有数据
- **重写规则**: 分页元数据以 primary 数组实际长度为准

## D. 部署态缺陷

### D1. 列漂移杀包
- **漂移对**: AA97.AAA97F/G → HM+WY; TC90.ATC90T1-3 → IMP
- **症状**: 7 个包体 INVALID → 对应页面写路径全死
- **根因**: dmp 导入时列结构与包源码不同步
- **重写规则**: ORM 映射从 DDL 生成(非手工维护)，列漂移在 CI 即发现
- **[2026-11-26 了结]** 旧侧已全部补列修复(卷53, 持久存活——夜同步保 DDL, 见 00 卷 §4.2);
  三条导入线端到端复活(卷58/60/61)。本条保留为"防御规则"价值, 症状描述=2026-11-10 时点。

### D2. dmp 重导抹测试登录
- **症状**: 每次重导后测试账号 enabled='F'
- **重写规则**: 测试环境用户与生产数据隔离

### D3. 导入引擎部署级故障
- **症状**: 所有 importId 一致静默失败，非 Lemis 异常被吞
- **根因**: ~~需 JVM 观测~~ **[2026-11-26 破案]** 真栈=部署副本陈旧影子 .class 的
  ClassCastException(PersistentSet→List, hbm set 映射被旧二进制强转 List); 删影子即活;
  引擎在真生产月跑 900+ 批(卷55)。备份库"全灭"是我们部署副本的局部假象。
- **重写规则**: 导入引擎自建，不依赖 POI 3.2(2008 年版)；错误必须完整透出;
  **部署件 WEB-INF/classes 遮蔽类不可信, 以 jar 内源码为意图基准**(卷55 定律)
