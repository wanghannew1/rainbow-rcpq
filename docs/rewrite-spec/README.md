## 勘误（2026-11-23 审计，对规格 9 篇逐条对账备份库源码+战役卷后）

规格大部分断言经 DB 源码/结构/行数实核**为真**（删除员工六表清单、COMFIRM_SH '4'≠打回、

   ——全库源码（含触发器）**无任何 INSERT INTO AA93**；该过程零引用 AA93，战役 21 卷实测
   200 读路径零变异。真实出处=战役 26 卷 **tdga 所得税参数页** AA93 实体(hbm)插入 PK 冲突
   （序列超前仍冲突，需 JVM 观测）——机制、归属、表象三处皆错。

   （user_tab_columns 实查）；真正漂移在暂存表 **TC90_BP 缺 ATC90T1-T6**（PKG_IMP 游标
   `SELECT * FROM TC90_BP` 取 REC.ATC90T1 → ORA-00904）。照规格给 TC90 补列修不了包。

## 通道级缺口（2026-11-23 用规格 01/04 对照移植面发现，未记账过）

   打回意见, TC90 不变可重提) 未移植；全后端无任何代码写 ATB912='4'。现有审核台
   (audit.js)只有 通过(doXinqCommit)/不通过(doXinqCancle=撤销+物理删待改造) 两键——
   审核台在月度节拍上是下一站，缺打回=退回修改重提闭环走不通。
2. **批量审核分派 PROC 通道未整体移植**：`PKG_RCPQ.PRC_COMFIRM_SH`(9 参, 按 ATB911

   doJsdy 覆盖；**'25' 姓名/身份证 4 表同步(AC01/TC90/TC90_LIST/TC93) 零覆盖**；
   '23' 终止的 COMFIRM_SH 分支(TC90_LIST 克隆终止+TC90_ZZ)与 terminateCancel 的
   等价性待核。
