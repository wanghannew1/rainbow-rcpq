## 3. 重写顺序（v2，含理由）

| 波次 | 模块 | 理由 | 验收焦点 |
|---|---|---|---|
| ✅ 1 | xa | 已完成：全链路+对照管线就绪 | — |
| ✅ 2 | az（a+b 合并） | 已完成：7 自定义用例移植+12 表落地+过程等价实现（PGRC_CREATE_CHILD/P_UPDATE_VALUE/P_DELETE）；旧库坏功能 2 处记录在案（PRC_个人信息变更不存在/拼音解挂静默空操作） | 全链路冒烟通过，行为对照扩展随对照管线统一回归 |
| **2** | **az（a+b 合并）** | 主档前置依赖；规模小（24 页/37 交互/1215 行 Java/**0 过程**）；6 个自定义用例是与 xa 同量级的显式用例移植 | 变更审核链（PRC_单位/个人信息变更 → Kotlin）、人员合并/删除审计 |
| **3** | **td/g** | 零自定义模块首次实战：验证通用分发器吃下"非 xa 元数据"；顺手补 Excel 导入（EasyExcel 替代 IOUtil） | 元数据迁移质量（8 store）+ EasyExcel 通道 |
| **4** | **td/a** | 业务链起点、最轻的业务模块（19 页/167 行/2 过程） | 协议编号生成、缴费计划继承 |
| **5** | **td/b** | 系统核心，**拆两波**：5a=b/a+b/c（新建/变更，TC90 写入+逐字段审计）→ 5b=b/d+e+f+l（审核/终止/续签/调转，含 PRC_GENERATE_TFMX 等过程移植决策） | 逐字段审计(AA10 对照)、合同状态机、18 个过程逐个评审（迁 Kotlin vs PL/pgSQL） |
| **6** | **td/l** | 纯通用只读，td/b 后数据齐备即白拿 | 只读元数据查询 |
| **7** | **td/c** | 页面最多但 Java 仅 746 行——大半是元数据驱动标准 CRUD；按时期/类型分 4-5 个批次迁元数据 | 53 子模块 datastore 批量迁移工具化 |
| **8** | **td/d** | 存储过程重镇（8 个），工资计算 PRC_SALARYCOMPUTE 是行为对照的重头戏 | 工资计算结果逐条对照 |
| **9** | **td/h / td/i / td/n** | 纯通用/独立/只读，零代码成本，可随基础设施成熟随时插队 | 工单流转状态、统计口径 |
| ⛔ | wts / TKTools / lemis_ext 等 | ADR D4 暂不迁移 | 用到再补 |

## 4. 规模总账

- **需重写业务面**：约 12 个模块、375 页、686 交互、其中自定义交互 66 个（xa 3 + az 9 + td/a 3 + td/b 25 + td/c 23 + td/d 6 — wts 的 3 个除外）
- **零代码模块**：114 页/185 交互（td/g+td/h+td/i+td/l+td/n）——成本集中在**元数据迁移**（约 135 个 datastore）而非代码
- **Java 总量**：约 5,800 行业务 Service（xa 642 + az 1,215 + td 3,962）
- **过程依赖**：td/b 18 + td/c 11 + td/d 8 + td/a 2 + td/n 1 ≈ 40 处调用点，涉及约 20 个 PL/SQL 过程——逐包评审清单见 database-migration-inventory.md §3

## 5. 与 ADR 的关系

- 原 ADR「模块顺序 xa→td/i→td/b→td/c+d」中的 **td/i 调整为波次 9**（纯通用零成本，无需早做）；
- **az 提前到波次 2**（主档依赖）；td/g 提前到波次 3（通用化验收）；其余一致。
- 已在 rewrite-decisions.md 追加修订记录。
