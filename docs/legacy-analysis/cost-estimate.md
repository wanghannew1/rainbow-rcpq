> 2026-11-09 固化。校准基准：GLM Coding Plan 实测数据。估算对象：xa 试点完成后剩余的全部重写工作
> （模块清单与波次见 module-inventory.md v2.1）。**每完成一个波次回填实际消耗，滚动修正估算。**

## 1. 校准基准（2026-11-09 上午实测）

| 量 | 值 |
|---|---|
| xa 试点收尾消耗 | 37.88M token = **1248 积分**（约 1 个会话） |
| 折合单价 | ≈ **33 积分 / 百万 token** |
| 内容构成 | query/update 分发语义、实体生成器修复、2 个自定义用例移植、行为对照管线闭环 |
| 含"试点税" | 幻影目录/CRLF/kotlin-spring 等调试回路 + 长上下文重发——后续模块不应重复此成本 |

**计件单位：1U = 1248 积分 ≈ 37.88M token**（一个"xa 收尾"当量的会话）。

## 3. 总账

| 口径 | 数值 |
|---|---|
| **积分** | ≈ **16,800**（区间 15,000–20,000） |
| **token** | ≈ **5.1 亿**（区间 4.5–6 亿） |
| **5 小时窗口**（2000 积分/窗口） | **7–10 个窗口** |
| **日历时间** | 每天 1 窗口 ≈ 2 周；每天 2 窗口 ≈ 1 周（纯 quota 口径） |

不含：人工决策时间（甲方确认、PL/SQL 评审业务判断、330 表确认）、旧系统维护。

## 4. 降本杠杆（目标 ~11U ≈ 14,000 积分）

1. **每模块开新会话**：避免长上下文逐轮重发（今早消耗中占比可观）——预计省 20–30%
2. **元数据走脚本不走 token**：568 store 迁移、黄金样本导出（scripts/db/ 已就绪）批量操作零 AI 消耗
3. **复制体合并**：td/c 的 tdcahService×4、tdblService×2 合并实现（v2.1 §6.2），少写即少花
4. **PL/SQL 评审人工先行**：中文包名即业务目录，人工读原文定迁移策略，AI 只做移植与对照
