> 2026-11-20 定稿。对照方法：以 `rainbowpq/docs/菜单按键分析/00~08`（53 页页面码表，
> **[实测]**=HTTP 重放验证/**[代码级]**=函数级分析）为东软侧按键真值，以
> `rcpq-web/src/main/resources/static/js/pages/*.js` 实源 + `HzController.kt`/各 `*Cases.kt`
> 过程移植实源为新侧真值，逐按键追到业务过程与库事务操作对照。

## 〇、结论速览

- 东软五险一金域 **40 页**（#1-33 + #44-48 + #52 + #53，划界见下），新系统以 **6 页工作台**承接
  （hz 六险种异动 / social 报盘 / jishu 基数 / yue 月转款 / insure 参保变更 / yy 异议）+ calc 险金测算（新独有）。
- **主链全通**：名册生成→成果确认→校验/提交→回盘文件导入→月情况/月转款确认→基数核对确认/导入/上下限→
  异议三链→退休停保/补收/变更参保地；过程面 110 个 /proc 全部注册。
- **缺口集中在六族**（详见 §八）：
  ①导出/打印族（东软 ~30 个 🔍 键，新系统仅报盘导出 4 文件）；
  ②报减名单族（东软独立报减页×5 + `atc9w1='3'` 名单生成，新系统仅社保/市医保走合同推导报盘）；
  ③单人补录×2（`PRC_市医保报增员工`/`PRC_省医保报增员工` 过程与页面均未移）；
  ④Excel→批次表**写入面**（基数 AA97_BP/TC0A_BP、补差 TJ0B2、减免 TC09_BP 的导入键，新前端只有"消费批次"键）；
  ⑤行级赋值键族（已申报/未申报、报增成功标记 ATC9WF、转入清标记、公积金封存启封赋值六键）；
  ⑥**TC06 特殊变动数据源断裂**（东软生成名册的三路数据源之一，新推送不读 TC06，且特殊情况页面未建）。
- **本次评估新发现的缺陷 4 项**（§八 P0/P1）：回盘后重推无后端锁且会把 '4' 已回盘行作废（旧系统
  有锁检查+只删暂存行）；推送无事务包裹（半账风险）；公积金名册查询列未别名导致防呆/状态列对公积金失效；
  工伤险种下"导入回盘文件"键可见但导入为静默 no-op。

## 三、生成侧范式差异（最核心的结构性差异）

东软五险一金生成名单 = **五个独立页面 × `PRC_*人员增减`(flag 1/3)**，新系统 = **hz 一页 × `/wb/hz/push` 合同推导**。
差异沉淀为六条：

1. **数据源收窄**：东软三路（TC06 特殊变动 + 变更源 + 合同主查询）→ 新单路合同推导（仅省工伤保留变更入队分支）。

3. **锁检查与重推**（本次评估复核发现，含 2001a43 防呆的缺口）：
   - 东软：过程内锁检查（`ATC9W8='4'` × 户头+区划+年月，L901-912）→ 拒绝重生成；

   阶段归属：结构性修复建议（一阶段忠实语义=原子，现实现反而弱于源）。
5. **删除语义升级**：东软物理 DELETE 暂存行 → 新逻辑删 atc9w8='9'（铁律 8 方向的正确改造，重推可追溯），
